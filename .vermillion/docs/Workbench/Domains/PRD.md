# Domain

Domain 是一个业务或跨模块领域（例如 UI/UX）的定义，用来把项目的长期规范交给相关的工单。它不挂在文档或代码路径上：一份文档里可能多处涉及某个领域但某次改动并不涉及，按路径匹配也判断不了语义，所以是否相关由管家凭对改动的理解判断。

每个领域一份文档 `.vermillion/docs/domains/<id>.md`：正文用自然语言说明这个领域覆盖什么、什么样的改动应该考虑它；头部 `standards:` 列出该领域的规范文档路径。随文档一起走 Git。

Workspaces → Domain 列出这个目录，可新建（生成模板并打开编辑）和编辑。角色 prompt 有独立入口。

管家拆单前读全部领域定义，判断工单涉及哪些，把这些领域的规范作为文档引用附进工单；Worker 开工前先读引用里的规范。设计伙伴在讨论中出现新领域或新规范时维护这两处。
