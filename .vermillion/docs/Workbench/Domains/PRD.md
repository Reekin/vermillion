# Domain

Domain 是一个业务或跨模块领域（例如 UI/UX）的定义，用来把项目的长期规范交给相关的工单。它不挂在文档或代码路径上：一份文档里可能多处涉及某个领域但某次改动并不涉及，按路径匹配也判断不了语义，所以是否相关由建单的 Worker 凭对改动的理解判断。

每个领域一份文档 `.vermillion/docs/domains/<id>.md`：正文用自然语言说明这个领域覆盖什么、什么样的改动应该考虑它；头部 `standards:` 列出该领域的规范文档路径。随文档一起走 Git。

工作台 → Domain 按标题栏选择的 workspace 列出这个目录。页面为左右主从布局：左列是领域列表，顶部提供新建（输入 id 后生成模板并打开编辑），行 hover 显示删除图标，删除前弹窗确认；右侧是选中领域的详情。删除领域移除领域定义文件、领域巡检指令和巡检配置，该领域的历史 Issue 与巡检记录保留。领域文件的新建与删除属于文档变更，随文档提交。角色 prompt 有独立入口。

工单 refs 包含与改动相关的领域规范，领域选择依据改动语义。

领域的 `standards:` 引用领域特有规范；通用验收规范由[开发与验收](../../../../docs/development.md)统一引用。引用关系不扩大领域的维护职责。

## Maintainer

领域详情依次展示简短领域说明、领域文件、Maintainer 设置与巡检记录，内容限制在可读宽度内。领域定义、检查依据和巡检指令使用统一的紧凑文件行，文件行是编辑入口；文件编辑沿用源码与 Markdown 预览双栏弹窗。

领域列表只识别 `.vermillion/docs/domains/` 直接子级的领域定义文件，不把子目录中的规范或其他材料列成领域。

Domain 详情分别展示“检查依据”和可编辑的“领域巡检指令”。前者引用 PRD 与 Standards；后者保存为项目内 `.vermillion/roles/maintainer/<domain-id>.md`，用于约定本领域的检查方法与重点。通用角色与领域指令的组合见[角色](../Roles/PRD.md#maintainer-巡检指令)。规范文档不充当角色 prompt。

详情里列出的领域定义、检查依据和领域巡检指令都以文件条目展示，点击条目直接打开统一的 Markdown 编辑界面，保存时各自写回原来的位置。

每个领域可配置 Maintainer，检查该领域的代码和文档是否符合领域定义、关联 Standards 与相关 PRD。Maintainer 设置直接在详情页操作，改动即保存：启用自动巡检、目录变更后巡检、定时间隔、允许自动开单四项为页面上的开关与下拉；触发目录显示已选数量并提供「选择目录」入口，授权范围显示已授权条数并提供编辑入口。设置旁提供立即巡检；巡检记录提供查看巡检会话与相关 Issues 的入口。

触发目录在弹窗中以目录树勾选：树来自 workspace 中 Git 已跟踪文件所在的目录，勾选父目录即覆盖其全部子目录，只保存父路径；部分子级勾选时父级显示半选。授权范围在弹窗中按行编辑。

触发目录只用于发现可能相关的变化，不改变领域按语义判断的方式。自动巡检可由目录变更和定时检查触发，默认定时间隔为六小时；相关变更合并处理，开发中的改动在交付后检查。定时检查关注新增变化与待复查问题，没有需要检查的内容时跳过。每轮使用独立 Maintainer 会话，保留检查范围、依据、结果与关联 Issue，供后续巡检接续。

巡检结果关联新建或补充的 [Issue](../Issues/PRD.md)，支持继续调查、授权范围内自动开单以及转交用户决策。巡检记录保存证据类型、已验证范围与待验证部分；历史 Issue 的处理原因可供巡检会话读取。检查方法、查重和分诊由 [Maintainer prompt](../../../../packages/workbench/roles/maintainer.md) 定义。

## 自动修复授权

每个领域独立配置自动开单开关与授权范围，范围明确允许修复的既定要求偏差；未开启或未填写范围时只巡检和分诊。授权配置与领域专属 prompt 分开保存，在巡检配置中编辑，并提供相同能力的 CLI。

Owner 的自动开单入口核对当前领域授权及 Issue、要求引用和证据记录；缺少授权或必要依据时不创建可执行工单，并返回原因。授权配置由用户管理，巡检指令不能将其改为更宽的范围。

自动开单保留来源 Issue、巡检会话、授权范围及判断依据，合同包含既定要求的固定版本引用、问题证据、预期恢复行为、允许修改范围与验收结果。生成的工单进入已有 Worker 调度、审阅与验收流程。领域授权允许范围内的修复自动进入执行，不需要逐张人工批准。

自动巡检启动受 workspace 的[自动推进开关](../Missions/PRD.md#执行控制)约束，领域自身配置继续决定巡检范围与触发条件。

巡检配置、授权、记录和 Issue 关联在重启后仍可查询，变化时界面自动更新。目录变更和定时到期会启动真实的 Maintainer 会话，手动立即巡检也一样。
