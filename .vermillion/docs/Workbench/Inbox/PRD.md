# Inbox

Inbox 集中展示所有 workspace 的决策卡和已合入通知，每项一张卡片。弹窗只展示待处理消息；全屏界面展示待处理消息与全部已处理记录。消息处理成功后从弹窗移除，已答复决策、已确认通知等已处理消息仅在全屏 Inbox 中保留查看，重新打开应用后仍可查看。

已合入通知主区展示工单标题、证据摘要和逐条验收结果，每条用验收时的实测描述而不是验收条目原文；commit、命令输出、review 意见处置、验收过程和 diff 概况放在可折叠的技术详情里。待处理通知的底部操作为知道了、附理由回滚；知道了将通知标记为已处理。Inbox 未处理计数不包含已处理记录。

某一项的数据损坏或加载失败时，Inbox 显示失败原因，不显示为空。Explorer 同样。

## 决策卡

决策卡要让用户看懂当前问题以及不同选择的结果。主界面不应直接铺开执行日志、源码路径和验收报告。

打开 Inbox 后，每张卡先显示所属工单，用简短文字说明发生了什么、为什么需要用户决定，再展示选项及各自影响。推荐项必须解释推荐理由；选项说明直接可见，不能只放在悬停提示里。

源码定位、测试结果与证据路径放在可展开的“技术详情”中；技术详情只放核对这个决定所需的信息，工作过程（跑过哪些命令、review 采纳记录、资源清理）属于工单证据，不进决策卡。需要深入了解时可以打开对应工单或执行会话；默认视图只保留做决定需要的信息。答复结果及相关工单状态在全屏 Inbox 的已处理记录中显示。

Worker 请求业务决策的卡片支持自由答复：用户只填备注、不选任何预设选项就能提交；预设选项与自由答复的送达和续做方式相同。答复作为下一条消息送达发起它的 Worker 会话，Worker 据此续做；技术问题或已有明确决定不重复询问用户。

合入故障的重试进度、立即重试、附说明转交 Agent 和取消遵循[合入进度与处置](../Missions/PRD.md#合入进度与处置)，与工单详情使用相同状态和操作。需要用户判断的合入阻塞及时进入 Inbox；自定义说明随转交实际送达处理该单的 Agent。

其他开工准备或工单运行故障在自动重试用尽时，只提供重试、取消操作，不显示备注输入或自由答复入口。GUI 与 CLI 均只接受预设操作；处理结果显示操作状态。

决策卡用于必须由用户选择的业务取舍、权限授权、需要用户判断的合入阻塞，以及自动重试用尽后的处置。技术问题、验证条件不足或尚未完成由执行者继续处理，不因审阅或验证达到固定轮数而要求用户放宽要求。卡片说明已经尝试的处置、剩余问题与每个选择的实际影响。

决策卡的字段：一句话问题、两三句上下文、每个选项的动作与后果、推荐项及理由、可折叠的技术详情、发起它的会话。GUI 与 CLI 读取相同内容。卡片上有「进入会话」可直接打开发起它的会话进一步沟通（fork 出的分支进思考页对应节点，冷启动的进 Workspaces → 会话），结论回写工单。

除 Worker 发起的决策卡外，工作台自己也会发：工单自动重试用尽仍未完成时询问再试或取消，前置工单被取消时询问依赖方如何处置，见 [工单](../Missions/PRD.md)。
