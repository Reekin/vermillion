# Inbox

Inbox 集中展示所有 workspace 里需要用户处理或知悉的内容：待决策的决策卡和已合入通知，每项一张卡片。已合入通知主区展示工单标题、证据摘要和逐条验收结果，每条用验收时的实测描述而不是验收条目原文；commit、命令输出、review 意见处置、验收过程和 diff 概况放在可折叠的技术详情里。底部操作为知道了、附理由回滚；知道了即从 Inbox 移除。

某一项的数据损坏或加载失败时，Inbox 显示失败原因，不显示为空。Explorer 同样。

## 决策卡

决策卡要让用户看懂当前问题以及不同选择的结果。主界面不应直接铺开执行日志、源码路径和验收报告。

打开 Inbox 后，每张卡先显示所属任务，用简短文字说明发生了什么、为什么需要用户决定，再展示选项及各自影响。推荐项必须解释推荐理由；选项说明直接可见，不能只放在悬停提示里。

源码定位、测试结果与证据路径放在可展开的“技术详情”中；技术详情只放核对这个决定所需的信息，工作过程（跑过哪些命令、review 采纳记录、资源清理）属于工单证据，不进决策卡。需要深入了解时可以打开对应工单或 agent 会话；默认视图只保留做决定需要的信息。选择后显示答复结果及相关工单状态。选项之外还有一条自由答复：用户只填备注、不选任何预设选项就能提交；预设选项与自由答复的送达和续做方式相同。答复送达当前问题的责任 agent：Worker 工作中的取舍交原 Worker 理解，需改合同时先上报管家；已由管家处理的合同问题直接回管家落实；主工作区修复问题回修复 agent。答复与合同落实、恢复执行的关系遵循[任务与工单](../Missions/PRD.md)。

决策卡用于必须由用户选择的业务取舍、权限授权和自动恢复用尽后的处置。允许范围调整、安排技术前置、已明确决定的落实由管家处理，不要求用户充当工单调度员。卡片说明已经尝试的自动处置、剩余问题与每个选择的实际影响；同一故障涉及多张工单时集中说明受影响工单。

尚未答复的卡片可由发起者通过 `decision.withdraw` 附原因撤回。撤回后从待决策列表移除，原因保留在相关问题的历史中；责任 agent 继续处理原问题，其他未解决阻塞仍有效。撤回不记录为用户答复，不代表验收通过或合同已更新。

决策卡的字段：一句话问题、两三句上下文、每个选项的动作与后果、推荐项及理由、可折叠的技术详情、发起它的会话。GUI 与 CLI 读取相同内容。卡片上有「进入会话」可直接打开发起它的 agent 会话进一步沟通，结论回写工单。

除 Worker 发起的决策卡外，工作台自己也会发：工单自动重试用尽仍未完成时询问再试或取消，见 [任务与工单](../Missions/PRD.md)。
