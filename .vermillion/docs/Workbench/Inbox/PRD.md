# Inbox

Inbox 集中展示所有 workspace 里需要用户处理或知悉的内容：待决策的决策卡和已合入通知，每项一张卡片。已合入通知展示工单标题、改动证据、review 意见处置、验收结果和 diff 概况，底部操作为知道了、附理由回滚；知道了即从 Inbox 移除。

某一项的数据损坏或加载失败时，Inbox 显示失败原因，不显示为空。Explorer 同样。

## 决策卡

决策卡要让用户看懂当前问题以及不同选择的结果。主界面不应直接铺开执行日志、源码路径和验收报告。

打开 Inbox 后，每张卡先显示所属任务，用简短文字说明发生了什么、为什么需要用户决定，再展示选项及各自影响。推荐项必须解释推荐理由；选项说明直接可见，不能只放在悬停提示里。

源码定位、测试结果与证据路径放在可展开的“技术详情”中；技术详情只放核对这个决定所需的信息，工作过程（跑过哪些命令、review 采纳记录、资源清理）属于工单证据，不进决策卡。需要深入了解时可以打开对应工单或 agent 会话；默认视图只保留做决定需要的信息。选择后显示答复结果及相关工单状态。选项之外还有一条自由答复：用户只填备注、不选任何预设选项就能提交，Worker 收到的是这段备注；预设选项与自由答复的送达和续做方式相同。

例如：“重启应用后，历史消息中的文件差异显示为空。修复需要额外修改保存和读取历史记录的代码，超出了这张工单当前允许修改的范围。”选项说明应交代继续本工单修复与拆成另一工单的区别，不能只写内部术语。

决策卡的字段：一句话问题、两三句上下文、每个选项的动作与后果、推荐项及理由、可折叠的技术详情、发起它的会话。GUI 与 CLI 读取相同内容。卡片上有「进入会话」可直接打开发起它的 agent 会话进一步沟通，结论回写工单。

除 Worker 发起的决策卡外，工作台自己也会发：工单自动重试用尽仍未完成时询问再试或取消，见 [任务与工单](../Missions/PRD.md)。
