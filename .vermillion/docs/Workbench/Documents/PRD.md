# 文档管理

Docs Explorer 按实际目录展示文档。Domain 可能跨越多个业务，文档需要支持独立于目录的领域标签。

## 目录与领域标签

在文档属性中设置多个 Domain 标签后，可以从各领域的关联文档列表打开同一文件。目录只负责浏览，不复制文档到不同领域目录。关联领域也不等于该文档是全领域必读规范。

移动文档后保持领域关联，历史工单仍能读取原版本。标签查询和修改提供对应 CLI 入口。

## Explorer 右键

有变更的文件提供“查看 Diff”，打开与已提交版本对比的弹窗，行为见 [Diff 弹窗](../../Interaction/DiffViewer/PRD.md)。

文件和文件夹提供“丢弃变更（Discard）”。点击后列出受影响文件，确认后恢复到 HEAD：修改文件恢复内容，新增文件删除，已删除文件恢复。已删除文件仍显示在树中，便于恢复。

只处理所选范围内未提交的文档变更，包括暂存内容，不撤销已提交 revision，也不修改 docs 外的文件。确认后目录树、变更标记和编辑器同步更新；未保存的编辑内容也须纳入提示，避免旧内容再次覆盖恢复结果。

Discard 提供相同的 CLI 操作。预览后文件发生变化时重新确认，不能带走其他文档的修改。

## 提交文档变更

提交弹窗提供“新任务”“补充到现有任务”“仅提交”三种方式。“仅提交”用于保存文档，不创建或关联任务、不派发工单，也不触发管家调整已有任务。

选择“仅提交”时只填写提交说明，不要求任务标题和摘要；按钮显示“提交”。所选变更形成普通 Git commit，支持同样的文件选择和说明自动生成。后续任务可以引用这些已提交文档；已有工单继续使用自己绑定的版本。

提交弹窗的文件列表提供“全选”和“反选”，旁边显示已选数量；操作只影响本次待提交文件。没有选中文件时不能提交或生成描述。

标题和摘要根据所选文件的路径、内容与实际变更，通过一次快速 LLM 请求自动填充。配置可用时首次打开弹窗自动生成，并提供“重新生成”按钮；调整文件选择后提示重新生成，不静默覆盖用户已经编辑的文字。结果只描述所选变更，不编造额外任务。补充到现有任务时生成变更说明，不修改已有任务标题。

生成中显示状态，失败可重试或直接手填，不阻塞手动提交。请求期间选择或文字发生变化时，不把旧结果覆盖到当前表单。

设置页提供“快速文本生成”，配置 URL、API Key 和模型，供这类短请求共用，暂时只支持 OpenAI Chat 兼容接口。配置在应用全局保存，不写进项目文档；Key 遮罩显示，调用由主进程执行，日志不记录 Key。未配置时提交弹窗提供前往设置的入口，保留已选文件和已填内容。配置读写与生成均有对应 CLI 路径。

提交期间按钮显示“提交中”，避免重复提交；失败留在弹窗内说明原因，保留输入。成功后关闭弹窗，保留当前讨论位置，在 Docs 面板底部显示可关闭的结果条：“已创建任务 · 标题”或“已补充任务 · 标题”，附“查看任务”入口。结果条保留到主动关闭或下一次成功提交，不依赖用户碰巧看到一闪而过的提示。

点击“查看任务”直接打开该任务详情，关闭后回到原讨论，不要求用户自己翻任务列表。成功反馈以实际创建或补充结果为准，不表示 Worker 已开始执行；执行状态在任务详情中展示。提交后的文件变更标记同步刷新。

“仅提交”成功后显示“已提交文档 · 提交说明”，附短 commit 标识，不显示任务入口。失败保留选择和说明。文档服务提供独立的提交 CLI 接口，不通过创建空任务实现。

## 实现方向

领域关联使用 `.vermillion/docs/catalog.json` 集中记录文档稳定 id、路径和 domains，随文档一起提交；移动和丢弃文件变更时同步维护对应索引。
