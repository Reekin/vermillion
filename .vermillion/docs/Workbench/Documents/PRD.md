# 文档管理

工作台 → 会话右侧的 Docs Explorer 浏览当前会话或草稿 workspace；它随会话页保持挂载，切换分页时隐藏。工作台 → 文档 列出标题栏 workspace 选择器指定项目的文档与决策记录。

Docs Explorer 按 `.vermillion/docs/` 的实际目录展示文件，有改动的文件带标记；点击文本文件打开编辑器，右键可在文件管理器中显示或用默认编辑器打开。领域与规范的组织见 [Domain](../Domains/PRD.md)。

变更标记包含已暂存、未暂存和未跟踪的文档变更。文档内容、Git 暂存区或当前提交变化后，通过事件自动更新标记；在外部 Git 工具提交后，无需切换页面或手动刷新。

## 文件打开与文本编辑

Explorer 内仅支持打开文本文件；PNG 等非文本文件仍显示在树中，点击不打开窗口、不切换当前文档、不弹提示，右键操作保留。

文本窗口提供带行号、按文件类型语法高亮和文内查找的源码编辑区；普通文本正常编辑。标题显示文档路径，底部显示保存状态并提供保存按钮，保留 Ctrl+S 保存。编辑区使用等宽字体，中文保持清晰可读，整体遵循 [UI/UX 规范](../../Foundation/UIUX/Standards.md)。

源码编辑区默认按可用宽度自动换行，不改变文件中的实际换行。文档窗口支持拖动边界临时调整宽高，关闭后重新打开恢复默认尺寸。

Markdown 文件默认左右分栏：左侧编辑源码，右侧实时预览当前编辑内容，无需先保存。预览呈现标题、段落、列表、链接、引用、代码块、表格与图片；文档内相对图片路径以该文档所在目录解析。源码中的 frontmatter 保留可编辑，预览正文不将其当作普通段落。两栏有清晰标签和独立滚动区域，窗口宽度适合并排阅读。

文件是否可作为文本打开由读取层统一判定，Explorer 与 CLI 沿用同一约束，不强制解码二进制内容。

## Explorer 右键

有变更的文件提供"查看 Diff"，打开与已提交版本对比的弹窗，行为见 [Diff 弹窗](../../Interaction/DiffViewer/PRD.md)。

文件和文件夹提供"丢弃变更"。点击后列出会被恢复的文件，确认后恢复到 HEAD：修改的还原，新增的删除，已删除的恢复。已删除文件仍显示在树中，便于恢复。只处理所选范围内的文档，不撤销已提交的 commit。

确认清单逐项显示还原修改、删除新增文件或恢复已删除文件；取消时不修改文件。丢弃包括所选文件的暂存与未暂存修改，范围外文件及其暂存状态保持不变。CLI 通过 `docs.discardPreview` 查询所选文件或目录的变更清单，再把确认清单中的文件路径传给 `docs.discard`；两者参数均为 `workspaceId` 与 `paths`，路径相对 workspace 根目录。

## 草稿与合入

文档修改按会话树隔离。同一棵树的设计会话、开工准备分支和 Worker 分支共用一份草稿；不同会话树互不可见，各自合入前不影响主干和其他树。草稿在该树首次写入文档时由工作台自动建立，不需要 agent 或用户预先创建，也不暴露目录位置。

会话页的 Docs Explorer 展示当前会话所属树的草稿：树有草稿时读写草稿，没有时读主干、首次写入时建立草稿。变更标记、Diff、丢弃变更都以草稿相对主干当前提交计算。工作台 → Docs 分页展示主干。按 commit 读取的文档（工单 refs）不受草稿影响。

agent 通过 `vermillion docs.read / docs.write / docs.commit` 读写和提交文档，调用时携带当前 sessionId，工作台据此定位草稿；不用普通文件工具直接修改 `.vermillion/docs`。没有 sessionId 的调用直接作用于主干。

提交即合入：选中的文档先在草稿上形成 commit，再合入主干，主干上的每次文档变更都来自某棵会话树的合入。合入与 Worker 成果合入共用同一串行边界；与主干内容冲突时合入不成立，原因回报给发起方，由它在自己的草稿里基于主干最新内容解决后重新提交。合入对执行中工单的通知规则见 [工单 · 流转](../Missions/PRD.md#流转)。

草稿全部合入且会话树不再活跃后，由现有 worktree 后台清理回收；有未合入修改的草稿保留。

## 开工与提交

Explorer 底部提供「开工」，对当前查看的会话节点发起执行。文档提交入口为 Explorer 右键菜单中的「提交」，文件、文件夹和空白区域均可进入。

「提交」打开提交弹窗：选择文件、填写提交说明，形成普通 Git commit，不创建工单、不触发执行。文件列表提供"全选"和"反选"，显示已选数量；没有选中文件时不能提交。开工不经这个弹窗，由开工分支自己判断范围并提交，见 [工作台 · 开工](../Think/PRD.md)。

提交成功后关闭弹窗，结果通过窗口底部的状态条反馈（见 [产品总览 · 状态条](../../Overview/PRD.md)），Docs 面板内不再出现结果条。失败留在弹窗内说明原因，保留输入。
