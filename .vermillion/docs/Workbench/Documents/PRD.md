# 文档管理

Docs Explorer 按 `.vermillion/docs/` 的实际目录展示文档，有改动的文件带标记；点击打开编辑器，右键可在文件管理器中显示或用默认编辑器打开。领域与规范的组织见 [Domain](../Domains/PRD.md)。

## Explorer 右键

有变更的文件提供"查看 Diff"，打开与已提交版本对比的弹窗，行为见 [Diff 弹窗](../../Interaction/DiffViewer/PRD.md)。

文件和文件夹提供"丢弃变更"。点击后列出会被恢复的文件，确认后恢复到 HEAD：修改的还原，新增的删除，已删除的恢复。已删除文件仍显示在树中，便于恢复。只处理所选范围内的文档，不撤销已提交 revision。

## 提交文档变更

提交弹窗提供"新任务""补充到现有任务""仅提交"三种方式。"仅提交"只填提交说明，形成普通 Git commit，不创建或关联任务、不触发管家。

Agent 通过 CLI 调用 `mission.create` 或 `mission.addRevision` 时，必须显式传入上下文提供的当前 `sessionId`，记录为该 revision 的来源会话，供管家、Worker 获取并生成返回设计会话的导航入口。CLI 要求填写该参数。[用户：而且调用cli创建时也应该输入sessionid]

文件列表提供"全选"和"反选"，显示已选数量；没有选中文件时不能提交。

标题和摘要可以根据所选文件的变更自动生成，需要在设置页配置一个 OpenAI Chat 兼容接口（URL、API Key、模型）；配置全局保存，Key 遮罩显示。配置可用时打开弹窗自动生成，并提供"重新生成"；不覆盖用户已经编辑的文字。未配置时弹窗提供前往设置的入口。

提交成功后关闭弹窗，结果通过窗口底部的状态条反馈（见 [产品总览 · 状态条](../../Overview/PRD.md)），Docs 面板内不再出现结果条。失败留在弹窗内说明原因，保留输入。
