# 文档管理

Docs Explorer 按 `.vermillion/docs/` 的实际目录展示文件，有改动的文件带标记；点击文本文件打开编辑器，右键可在文件管理器中显示或用默认编辑器打开。领域与规范的组织见 [Domain](../Domains/PRD.md)。

## 文件打开与文本编辑

Explorer 内仅支持打开文本文件；PNG 等非文本文件仍显示在树中，点击不打开窗口、不切换当前文档、不弹提示，右键操作保留。[用户：仅支持打开文本文件，点非文本文件没反应]

文本窗口提供带行号、按文件类型语法高亮和文内查找的源码编辑区；普通文本正常编辑。标题显示文档路径，底部显示保存状态并提供保存按钮，保留 Ctrl+S 保存。编辑区使用等宽字体，中文保持清晰可读，整体遵循 [UI/UX 规范](../../Foundation/UIUX/Standards.md)。

Markdown 文件默认左右分栏：左侧编辑源码，右侧实时预览当前编辑内容，无需先保存。预览呈现标题、段落、列表、链接、引用、代码块、表格与图片；文档内相对图片路径以该文档所在目录解析。源码中的 frontmatter 保留可编辑，预览正文不将其当作普通段落。两栏有清晰标签和独立滚动区域，窗口宽度适合并排阅读。

### 已定的实现方向

文件能否作为文本打开由文档读取层统一判定，不能把二进制内容强制解码后交给编辑器；Explorer 使用同一判定结果决定是否打开，CLI 的文档读取入口沿用这项文本约束。文本编辑与 Markdown 渲染优先复用项目已有能力及成熟组件，样式接入应用主题。

## Explorer 右键

有变更的文件提供"查看 Diff"，打开与已提交版本对比的弹窗，行为见 [Diff 弹窗](../../Interaction/DiffViewer/PRD.md)。

文件和文件夹提供"丢弃变更"。点击后列出会被恢复的文件，确认后恢复到 HEAD：修改的还原，新增的删除，已删除的恢复。已删除文件仍显示在树中，便于恢复。只处理所选范围内的文档，不撤销已提交 revision。

## 提交文档变更

提交弹窗提供"新任务""补充到现有任务""仅提交"三种方式。"仅提交"只填提交说明，形成普通 Git commit，不创建或关联任务、不触发管家。

Agent 通过 CLI 调用 `mission.create` 或 `mission.addRevision` 时，必须显式传入上下文提供的当前 `sessionId`，记录为该 revision 的来源会话，供管家、Worker 获取并生成返回设计会话的导航入口。CLI 要求填写该参数。[用户：而且调用cli创建时也应该输入sessionid]

文件列表提供"全选"和"反选"，显示已选数量；没有选中文件时不能提交。

标题和摘要可以根据所选文件的变更自动生成，需要在设置页配置一个 OpenAI Chat 兼容接口（URL、API Key、模型）；配置全局保存，Key 遮罩显示。配置可用时打开弹窗自动生成，并提供"重新生成"；不覆盖用户已经编辑的文字。未配置时弹窗提供前往设置的入口。

提交成功后关闭弹窗，结果通过窗口底部的状态条反馈（见 [产品总览 · 状态条](../../Overview/PRD.md)），Docs 面板内不再出现结果条。失败留在弹窗内说明原因，保留输入。
