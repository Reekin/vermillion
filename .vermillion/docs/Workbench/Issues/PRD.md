# Issues

Issue 是用户提出或 agent（Maintainer、Liaison）收集的议题，保留发现、调查、决策及执行关联的记录。处理状态为待处理、调查中、待决策、已开工、关闭、重复；建议作为议题类型区分。Issues 入口显示未读数量。开发可由讨论后开工、用户手动建单，或领域授权范围内的 Owner 自动开单触发。

## 列表与详情

点击议题以弹窗打开详情，保留底层页面的筛选和位置。“进入讨论”关闭弹窗并切换至关联会话。

工作台 → Issues 按标题栏选择的 workspace 展示议题，默认突出待用户决策的项，并可查看全部议题、调查中、已开工及建议。支持标题搜索、状态与领域筛选及手动新建。列表显示标题、来源、领域、状态、更新时间与未读标记。

详情展示问题与影响、要求依据、证据及验证程度、建议方向和活动记录，并关联来源巡检会话、讨论会话与工单。已有 Issue 支持持续补充证据和活动；问题归并规则由对应收集角色的 prompt 定义。

## 讨论与处理

详情中的“进入讨论”在工作台会话页创建关联的设计伙伴会话，带入问题、依据与证据；已有讨论时入口为“继续讨论”。用户在会话中明确预期与方案后开工，工单回链 Issue，议题状态变为已开工。讨论本身不改变待处理状态。保留用户手动建单并关联议题的能力。

用户可关闭议题或标记重复并关联原议题，保留处理原因。已接受的取舍供 Maintainer 后续检查参考，避免重复提报。

## Owner 分诊

有证据且违反既定要求、修复方向确定的问题，在领域自动修复授权范围内可直接转为工单；证据不足的进入调查中，保留调查会话与待补证据。需求含糊、文档冲突、行为取舍和需要新增授权的议题进入待决策，详情展示具体决策问题，并可进入设计伙伴会话继续讨论。优化建议留在建议列表，默认不自动开单。

自动开单后 Issue 显示已开工并关联实际工单；已开工不代表问题已解决。授权与判断依据在活动记录中可追溯。用户决定及关闭原因持续保留供后续巡检读取；创建、更新、讨论关联和工单关联在应用重启后仍可查询。

Issue 的创建、查询、更新、关联讨论与工单，以及领域巡检配置、触发和记录查询均提供 CLI 调用路径。
