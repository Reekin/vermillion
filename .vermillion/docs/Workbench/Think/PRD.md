# 工作台

工作台是主页，用于讨论需求、修改文档并查看执行。左侧会话列表常驻，右侧顶部依次为会话、工作、领域、角色、Issues、自动化、管理，默认打开会话。文档通过会话页右侧的 Docs Explorer 浏览和编辑，没有单独的文档分页。会话页由消息阅读区和右侧 Docs Explorer 组成；切换分页后再回来，查看位置和未发送草稿都还在。消息区在任何宽度下都保持左右留白，文字不贴边、不被裁切。

会话页以外的分页由标题栏的 workspace 选择器决定浏览和编辑哪个项目。选择器只做切换；添加 workspace 在会话输入器和管理分页进行，移除只在管理分页进行。

各处的 workspace 列表（标题栏选择器、输入器的 workspace 选择、会话列表筛选下拉）使用同一顺序：按 workspace 内会话的最近更新时间从新到旧排列，更新时间的定义见[会话列表](#会话列表)，已归档的会话不计入；没有会话的 workspace 排在最后，按添加时间从新到旧。列表展开期间顺序不变，收起后再按最新活动更新。会话列表筛选下拉的「全部」固定在第一项。

会话列表筛选与输入器的 workspace 选择使用相同的搜索列表，支持按名称和路径搜索。筛选保留「全部」，输入器保留「无 workspace」和「新建 workspace」。条目右侧在鼠标悬停或键盘聚焦时显示「打开目录」图标按钮；点击在文件管理器打开该目录，已有该目录窗口时唤起已有窗口，不改变所选 workspace 或会话筛选。打开目录也可通过 CLI `file.runAction`（`action: "open"`，`path` 为目录路径）调用。

点击新建会话进入草稿态，在输入器选择 workspace，发送首条消息时创建会话。列表筛选选中具体 workspace 时，新草稿使用它；「全部」下默认上次使用的 workspace。

## 开工

开工成功立即创建可见的工作入口，准备与关联工单的管理见[工作与工单](../Missions/PRD.md#工作)。工单暂停、恢复和取消遵循[执行控制](../Missions/PRD.md#执行控制)，普通聊天 Stop 保持会话本身的含义。取消的准备与工单退出活动 Worker 列表，历史保留。

讨论收敛后，用户点击右侧 Docs 底部的「开工」按钮，或直接对设计伙伴说“把 ABC 开工做掉”。两条入口都落到同一个动作 `work.start`，参数是当前会话、fork 点 turn 和一段可选的范围描述。聊天入口的调用与回复由[设计伙伴指令](../../../../packages/workbench/roles/zh/design-partner.md)规定。

输入器为空时，「开工」直接登记请求，向准备分支发送配置的准备提示。有未发送内容时，同一按钮显示「发送并开工」，应用直接登记请求，将用户输入与准备提示合成准备分支的第一条消息，保留附件、技能引用及本次模型选择。按钮入口无需先让设计伙伴运行一轮；请求未成功接收时保留输入内容。

已有讨论从当前查看节点 fork 出准备分支，即使它是末端；所选节点仍在运行时，等待该 turn 结束再 fork。准备分支保留原角色指令，使用 `work-preparation.md` 配置的准备消息及本次范围。查看位置停在原节点，用户接着提问仍然延伸讨论线。新建会话直接以合成消息开始准备，无需先生成讨论 turn。

准备阶段产出相关设计提交、关联工单和所需的 worktree 登记，操作步骤由[开工准备指令](../../../../packages/workbench/roles/zh/work-preparation.md)规定。开工入口不要求用户在弹窗里手选文件。一次开工拆出多张工单时，准备分支直接执行第一张工单，其余工单各自从准备轮末端 fork 出一个执行分支，以合同作为第一条消息。

开工和后续执行都不主动压缩上下文，分支保留 fork 点之前的讨论内容。准备轮结束后，工单排队等待执行，后续流程见 [工单](../Missions/PRD.md)。

设计伙伴改文档时知道自己 fork 出了哪些分支，会在回复里说明对哪张工单有影响；用户也可以直接切到 Worker 节点提问或纠正。文档提交对执行中工单的通知与续做规则见 [工单 · 流转](../Missions/PRD.md#流转)。

## 当前工作状态条

准备及固定 Worker 分支的输入框上方显示紧凑工作条，与底部配置行分开。左侧是工作图标、真实工作名称及业务阶段，运行或等待情况作为辅助信息；右侧保留适用的任务操作、查看和更多菜单。准备未建单时使用开工范围或来源会话名称，取消收进更多菜单。窄窗口名称可截断，状态与操作保持可见；完成后收为结果条并保留查看，不重复显示“当前工作”标签或用它代替工作名称。

工作条只出现在工作台登记过的准备分支和 Worker 分支上。原设计讨论和普通 fork 不属于任何工单，也不显示工作条。查看执行分支的历史节点时，工作条仍展示本工单的实时状态；历史节点只用于阅读或 fork 出去讨论，不能把执行转移过去。

查看详情分别展示任务进展、会话是否在运行、阻塞原因和可以做的下一步；处于执行阶段但这一轮已经结束时，明确显示尚未交付。

准备或单张工单的暂停、恢复、取消作用于当前目标；整份工作的操作与监工入口在工作详情。没有正在运行的轮次时也可以操作，可用动作和不可用原因与工作详情一致；切换节点或重启不改变任务状态。聊天发送与 Stop 就是普通会话行为，具体边界见[执行控制](../Missions/PRD.md#执行控制)。

有待决策时提供问题及明确的“回复此决策”入口，多张卡选择具体目标；普通输入默认仍是聊天，不自动替用户提交决策。答复的登记与交付遵循[决策卡](../Inbox/PRD.md#决策卡)，回复目标为该工作的固定执行会话。

## 会话列表

新建会话旁的「全部」/ workspace 下拉只筛选会话列表，不切换当前阅读的会话，也不改变其他分页的 workspace 浏览范围。「全部」展示所有 workspace 的会话，不作为文档或角色的全局编辑范围。

进入工作台时一次列出当前筛选范围内的全部会话树，不分页。之后某个会话新建、有活动、完成、归档或改名，只更新它自己那一行：其他行、已展开的子会话和滚动位置都不变。当前打开的会话因自身活动排到前面时，列表滚动到它可见；其他会话的重排不移动视口。

用户发起的会话树与 agent 独立启动的会话统一展示，置顶的排最前，其余按最近更新时间排序。更新时间取整棵树里最近一次用户消息发送成功或轮次完成的时间；消息发送成功就立即更新排序，不等 agent 回复完，流式输出期间不改变时间。会话行展示标题、状态、相对时间和适用的角色标记。「全部」筛选下，标题下方显示 workspace 名；选定具体 workspace 时不显示。

一棵会话树在列表里只占一行（见「会话树」）；某个会话派出的 subagent 缩进挂在它下面。有子会话的行左侧显示展开／折叠按钮，默认折叠；点按钮只展开或折叠，点行才打开会话。

会话行左侧的状态灯反映整棵树：有分支在运行时为黄色，有未查看的新完成内容时为绿色，都没有时不显示。缩进的 subagent 行显示它自己那棵树的状态。打开树里任意一个会话就清除绿点；之后树内又有分支完成、且完成时不在当前可见路径上，绿点才重新出现。清除列表绿点不会把树里没看过的节点标为已读，节点的已读规则见「会话树」；打开父会话也不清除 subagent 行的绿点。监工分支的运行和完成不点亮状态灯，也不更新这一行的更新时间。

右键菜单：重命名、置顶/取消置顶、复制会话 id、复制内部会话 id、归档、刷新运行环境、重新连接、打开 rollout 文件。归档后从列表移除。

列表中任意会话都可以重命名，包括本次还没打开过的会话。重命名在弹窗中编辑当前标题，确认后立即生效，重启后保留；取消或留空不改标题。自动生成的标题只用于还没有标题的会话，不覆盖用户改过的名字。重命名不改变排序、置顶、归档状态和会话树结构，提供对应 CLI。

## 会话历史刷新

打开已有会话、消息还没准备好时，消息区中央显示轻量动效和「正在加载会话」。下方列出打开会话、加载历史、显示消息三个阶段：当前阶段显示已用时间，完成的阶段固定耗时，未开始的显示待开始。详情行说明正在做的事，例如核对历史、等待引擎返回、转换消息；当前路径包含多个分支时显示已就绪数量和总数。阶段和数量都来自实际加载过程，不显示估算的百分比或剩余时间。

计时和详情变化时布局保持稳定，不跳动、不重播入场动画。很快完成的切换不闪加载画面；已有可读内容时直接展示。失败时停止动效和计时，提供重试。动效遵循系统的减少动态效果设置。

打开 Codex 会话时展示引擎中的最新历史，包括中途中断的轮次；会话在 Vermillion 之外被修改过时，也以最新内容为准。

切回已经加载过的会话时，立即显示已有内容和上次的查看位置，同时在后台核对历史，有变化再更新受影响的部分。正在输出的会话切回来后继续实时更新，不等整条历史重新加载。

核对和刷新期间，已显示的内容、后台运行和输入草稿都不受影响。刷新失败时提示原因并可重试。刷新不会删除会话历史、分支关系或 Codex 自己的数据。

## 搜索

新建会话下方放置搜索按钮，点击打开搜索弹窗。顶部输入关键词，下方左侧按「工单」「会话」「文档」分类展示结果，右侧预览选中结果的上下文。两侧分别滚动并隐藏滚动条，浏览左侧时右侧保持可见。

搜索只匹配用户在界面上读得到的内容，不匹配存储格式里的字段名、转义字符、id 和其他元数据。工单搜索匹配工单详情显示的文字：标题、目标、范围、验收要求与验收结果、审阅意见、决策和成果摘要。会话搜索匹配 Vermillion 会话的用户消息、agent 回复，以及工具调用操作的对象（文件、命令、搜索词、网址）；步骤描述里由程序生成的动作和结果（如「读取」「输出 3 行」）只用于显示，不参与匹配；不包含其他应用的会话。文档搜索匹配 `.vermillion/docs` 中的文本文件内容。

工单结果每条对应一段显示文字，标明它在详情中的位置（如「目标」「验收 3」「审阅」），不用存储文件行号定位。

会话结果分两层：会话树，以及树下的命中消息。树标题行显示与会话列表一致的标题和命中数量，可以折叠。树下每条结果对应一条消息，同一条消息多处命中只出一条；结果前标明来源（你、agent 回复、工具调用），摘取的是消息显示出来的文字，关键词用清晰的底色高亮，下方写所属轮次和时间。不按分支分层，不用文件名、id 或存储文件行号当标题或定位。摘取保留命中位置前后可读的上下文，过长时省略两端。

会话树按最近活动时间倒序排列，时间口径与[会话列表](#会话列表)一致。树内的命中按所属分支的最近活动时间倒序，同一分支内按原文顺序。多个分支共享的祖先里的同一处命中只显示一次。

各分类初始最多显示 10 个顶层结果（会话分类按会话树计），「展开更多」只展开当前分类，并且可以一直取到全部结果，不会因为前面的会话命中多而漏掉其他会话。

单击匹配项选中并更新右侧预览，鼠标经过不改变选中项。会话结果的预览显示命中消息的完整文字，前后相邻消息淡化显示，关键词以清晰底色高亮，命中消息保持在可见位置；预览是纯文本，不加载真实会话，不渲染成聊天消息。工单结果的预览同样显示命中那段文字的全文，前后相邻段落淡化显示。文档结果预览命中位置附近的原文。

双击匹配项或使用打开动作进入对应对象：工单打开详情，文档打开编辑器并定位命中处，会话打开所属分支并定位到命中轮次。rollout 文件路径属于详情信息。弹窗底部给出选择、打开、关闭的快捷键提示。

结果边搜边出现，不等全部扫完。搜索进行中弹窗照常可用，已出现的结果可以选中和预览，新结果到达不会改变当前选中项。底部显示搜索范围与耗时。修改关键词后立即按新关键词搜索，不等旧搜索结束；中文输入法还没上屏的内容不触发搜索。

搜索、后续结果获取与上下文预览同时提供 CLI 入口。

## 输入器

其他会话在持续输出时，当前的输入和阅读保持流畅。消息区只实时显示当前查看路径的内容；后台分支只提示运行、完成、失败、中断、等待审批或等待输入等状态变化。切到后台分支时显示它已有的完整内容，并继续实时更新。切到历史节点后，该节点之后的新输出按后台内容处理。实现要求见[界面响应规范](../../Foundation/Performance/Standards.md)。

每棵会话树有一份未发送草稿，包括文字、图片等附件和已选技能。同一棵树里切换节点或分支，草稿不变；切到另一棵树显示那棵树的草稿，第一次进入时为空，切回来恢复原样。新建会话有单独的草稿。切换工作台分页不丢草稿；重启应用后不要求恢复。

消息发给点击发送时所在的位置。发送成功或进入发送队列后，清空这次提交的内容，其他树的草稿和提交后新输入的内容不受影响。图片跟随所属草稿保留，切节点、切分支、切树和刷新历史都不会清掉，恢复后仍可预览和发送。

不提供 Attach files 按钮，附件通过拖拽和粘贴添加。

输入器是一个带细边框的整体容器，文本区和发送操作在同一个框里。容器下沿左侧显示快捷键提示，右侧显示发送箭头或停止方块。

输入框下方常驻一行状态与配置。左侧显示当前会话状态：空闲和新建草稿显示「就绪」，运行、审批和错误显示实际状态。发送结果、警告和错误统一显示在窗口底部状态条的[输出](../../Overview/PRD.md#输出)里，输入器不重复显示。右侧是 workspace 选择和一个模型配置控件：控件显示模型名，后跟引擎支持的推理档位与速度（如「GPT-5.6-Luna Max · 标准」），点击展开面板分别选择模型、推理和速度；控件轻量透明，hover 和 focus 反馈清楚；上下文用量图标位置固定。常规窗口宽度下状态与配置保持一行；状态、提示和用量变化时不新增行，输入框不移动；窗口变窄时配置控件整个换行。字体与控件规格见 [UI/UX 规范](../../Foundation/UIUX/Standards.md)。

### 模型配置

新建会话草稿的模型、推理、速度默认取设计伙伴角色的配置，规则见[角色与执行 · 模型配置](../Roles/PRD.md#模型配置)。用户可以在发送前调整；创建会话、首条消息和后续消息都使用输入器当前显示的配置。

每一轮对话完成后，Vermillion 记录这一轮实际使用的模型、推理档位和速度。切换到节点时，输入器恢复成该节点当时的配置；多个分支共享的节点显示它自己的记录，不受所在分支当前配置影响。记录在重新打开会话和重启后仍然有效。

Vermillion 没有记录的节点（引擎派出的 subagent、在 Vermillion 之外产生的轮次、早期历史）取引擎历史里这一轮实际使用的配置；引擎也没有这一轮的记录时，取该会话最近一轮的实际配置。这些节点不套用角色默认配置，向 subagent 继续发消息时沿用它自己的模型。

之后用户可以手动调整。调整只影响接下来的发送，不改历史节点的记录；发送、创建分支的过程中始终使用提交时的配置。恢复配置不改变当前分支和角色。

## 会话树

从同一个会话 fork 出的所有分支组成一棵会话树。树上每个节点是一轮对话，fork 出的分支挂在 fork 点那一轮下面。引擎只需支持从某一轮 fork，树由 Vermillion 自己维护，数据模型见[架构](../../Foundation/Architecture.md#会话树)。

### 加载

打开会话时，消息区先显示当前查看路径的消息，不等整棵树；树区域单独显示加载状态，整棵树就绪后一次展示，不显示缺分支的半成品。切到还没加载的分支时，只等这个分支需要的内容。加载期间其他界面照常可用，也不会出现上一个会话的树。

已经显示的树在刷新期间保持可浏览、可跳转，包括后台刷新历史、准备分支转为 Worker 执行等情况；新结果就绪后整体替换，并保留仍然有效的选中节点和查看位置。加载失败时提示原因，已显示的树继续可用，不会一直停在加载状态。

### 显示与导航

节点图默认隐藏 Worker 和监工分支。图下方列出这棵树里还没结束的 Worker，包括进行中的准备，以及排队、执行、等待合入、等待用户和暂停的工单；点击后跳到该分支的最新节点，并临时显示这个分支和连到它的祖先节点。切到其他分支后，它重新隐藏。双击图中节点跳到该位置。

「显示工单会话」开关默认关闭，打开后显示这棵树的全部 Worker 和监工分支，包括已结束的。Worker 自己的节点标 W，监工自己的节点标 M，它们继承的节点保持原样式。切到监工分支时，临时显示该分支和连到它的祖先节点，切走后重新隐藏。

所有节点用同一套状态颜色：进行中黄色，已完成未读绿色，已读中性色。当前查看位置用单独的轮廓标出，不覆盖状态颜色。已读按节点记录：查看当前路径会把路径上已完成的节点标为已读，其他分支和还没看到的后续节点不受影响；运行中就在看的节点，完成后算已读。

跳转只改变查看位置，不影响正在运行的分支。每棵树记住上次的查看位置，重新打开时回到那里。查看位置同时确定分支和轮次：消息区显示从根到这一轮的内容，之后的隐藏。准备分支和执行分支的活动不会改变用户正在看的位置。

### 节点菜单

节点右键菜单提供「复制 session id」「复制内部 session id」「Open rollout」「隐藏节点」。前三项作用于被右键的节点所在的会话：session id 是引擎的会话 ID，内部 session id 是 Vermillion 的会话 ID；「Open rollout」用与会话列表相同的方式打开该会话的 rollout 文件，不改变查看位置。以上操作都提供对应 CLI。

「隐藏节点」对根节点以外的任意节点可用。隐藏后，这个节点和它之后的所有节点都不再显示，包括从这些节点 fork 出的分支，以及之后在它们下面新产生的节点。如果查看位置在隐藏范围内，回到被隐藏节点的上一个节点；从这里继续提问会 fork 出新分支，隐藏的轮次不进入新分支的上下文。刷新、重新打开和重启后仍保持隐藏。

隐藏只影响 Vermillion 里的会话树显示：不归档或回退引擎中的会话，不修改 rollout，不影响其他分支的上下文。会话列表仍按整棵树统计更新时间、状态灯和未读提醒，隐藏范围内的活动也计入，打开这棵树时绿点照常清除。隐藏和节点菜单使用同一个 CLI 操作。

### 提问与分支

在当前位置追加提问：位置在所在分支末尾时直接发送；否则从这一轮 fork 出新分支再发送，新分支成为当前位置。不能从正在进行的轮次 fork。多个分支可以同时运行，在一个节点提问后切到另一个节点再提问，两条分支各跑各的。

普通 fork 保留对话上下文和模型配置，不属于原来的开工请求或工单；要继续原工单，回到它的 Worker 分支。只有工作台登记的准备、Worker 和监工分支才按工单会话规则隐藏和显示状态，普通讨论不会因为相关工单结束而被隐藏。

在非末端节点提问后，提交位置下立即出现并选中一个新节点，显示刚提交的消息和「正在创建分支」，输入框马上可用。创建分支和发送在后台完成，期间可以浏览、切换节点，也可以在别的节点继续提问。完成后这个节点原地转为正式节点，接着显示回复。用户已经切到别处时不会被拉回来。失败时在消息上显示原因，可以重试，消息内容保留。

新节点还在创建或发送时，选中它按 Stop，或右键「取消发送」，会取消这次发送；失败的节点右键可以「移除」。取消或移除后这个节点从树上消失，不会因为后台稍后完成又冒出来；清理失败时提示原因并可再次清理。消息的文字、附件和配置可以恢复到输入器重新编辑，不覆盖输入器里已有的新草稿。如果当时正选中这个节点，查看位置回到提交位置。其他分支不受影响。

消息已被引擎接收、产生了正式的一轮之后，Stop 只中断这一轮，节点和消息都保留，不想保留时用「隐藏节点」。提交、重试、取消和移除都提供对应 CLI。

## 消息区

用户消息与 agent 回复形态不同：用户消息靠右，以浅底气泡显示，发送时间在气泡下方淡字显示；agent 回复按正文排版占满阅读宽度，末尾一行放复制等操作以及本轮实际使用的模型、推理档位（来源同[模型配置](#模型配置)）和完成时间，用时写在完成时间后的括号里（如「14:43:51（1 分 27 秒）」）。消息时间精确到秒，当天只写时刻，其余加「昨天」或日期。会话标题栏显示会话标题，未命名时显示「新会话」。

一轮里 agent 在最终回复之前的中间消息、思考和工具调用统称执行过程。运行中逐步实时显示；这一轮结束后，执行过程收成回复上方的一行摘要，按动作类别计数并写明用时，例如「读取 2 个文件 · 运行 1 条命令 · 1 分 27 秒」，点击展开或收起。

展开后保留执行时消息与工具步骤的先后顺序，结束、刷新和重新打开会话都不改变这一顺序。每步一行：动作图标、动作、对象和结果，例如「读取 README.md · 输出 3 行」「运行 git status --short · 无输出」；中间消息以正文短句列在对应位置。失败的步骤标出失败结果。编辑步骤的结果是增删行数，例如「编辑 asset-record.md · +3 −5」；点开显示这次改动的 diff，新增和删除行按 [Diff 配色](../../Foundation/UIUX/Standards.md#视觉规则) 区分，改动涉及多个文件时逐段标出路径。点开单步才显示命令原文与输出；工具输出里的图片（如截图）在展开的步骤中以图片显示，一步可含多张。步骤内容在点开时才加载，步骤很多的长轮次也能流畅展开。步骤写法遵循 [UI/UX 规范 · 技术数据](../../Foundation/UIUX/Standards.md#技术数据)，会话区自有的过程描述使用中文。

## 图片预览

消息和输入器中的图片点开后，在预览图片上右键提供「复制图片」，把图片本身复制到系统剪贴板，可粘贴回输入器或其他支持图片的应用。复制后预览保持打开；失败时显示原因。复制图片提供对应 CLI。

## 消息中的文件链接

消息里的本地文件链接按「路径 + 可选位置」解析：末尾整体匹配 `:397`、`:10-11`、`:12:5`、`#L42`、`#L42-L50` 时视为文件上的位置，不参与打开；末尾不构成位置时，整串按路径处理。

`#` 后面不是行号时按路径原样处理，不剥离文档锚点。

盘符路径前面多写一个斜杠（`/I:/…`）按盘符路径处理。

点击用默认编辑器打开该文件，位置不参与打开。悬浮显示完整目标：绝对路径，带位置或不带。右键菜单提供「复制路径」和「复制文件位置」，复制成功后给出提示。

打不开或无法定位的目标（文件不存在、相对路径、锚点）原样显示目标本身与失败原因，并可以右键复制，不留下一个看不出指向哪里的链接。

## 消息中的文件变更

一轮改了文件时，消息下方列出变更：文件数与增删行数、可撤销本轮改动，每行一个文件（变更类型、相对 workspace 的路径、增删行数），点击打开 Diff 弹窗，见 [Diff 弹窗](../../Interaction/DiffViewer/PRD.md)。

## 消息中的工单

消息里出现的工单 id 渲染成工单标记，点击进入工作台 → 工作并定位工单详情，见 [工单](../Missions/PRD.md)。用户与 agent 会话使用相同行为。

## 消息中的会话导航

Agent 建议用户前往其他会话继续讨论时，可调用工作台 CLI，在发起调用的当前会话消息区插入“前往会话”组件。组件展示目标会话标题、角色及可选的简短前往原因，点击即可打开目标会话。组件随所在消息保留，再次打开来源会话时仍可使用。

所有目标都进入工作台 → 会话：会话树成员切到对应节点，冷启动的 agent 会话直接选中目标。导航同步目标所属 workspace，用户可直接阅读和继续对话。

工作台向 agent 上下文注入当前会话的 `sessionId` 和所属 `workspaceId`，工单上下文直接提供来源设计会话和执行分支的会话 ID。Agent 使用已提供的 ID 创建导航组件，无需先查询目标会话。CLI 创建导航组件时显式传入来源 `sessionId` 和目标会话 ID。

## 管理

工作台 → 管理 展示标题栏选择的 workspace 的根路径，提供「移除 workspace」按钮。移除前弹窗确认，确认后从工作台注销该 workspace，不删除磁盘文件。

## 桌面提醒

窗口不在前台时才弹桌面提醒，两种情况：自己的会话完成一轮；Inbox 出现新的决策卡或已合入通知。agent 会话完成不提醒。

同样的事件也会推送到已配对的手机，推送条件见[手机远程 · 推送](../Mobile/PRD.md#推送)。
