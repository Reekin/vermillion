# 工作台

工作台是主页，用于讨论需求、修改文档并查看执行。左侧会话列表常驻，右侧顶部依次为会话、工作、文档、领域、角色、Issues、自动化、管理，默认打开会话。会话页包含 SessionPane 和 Docs Explorer；切换分页时保持挂载，保留查看位置与未发送草稿。其他分页使用标题栏的 workspace 选择器指定当前浏览和编辑范围。

点击新建会话进入草稿态，在输入器选择 workspace，发送首条消息时创建会话。列表筛选选中具体 workspace 时，新草稿使用它；「全部」下默认上次使用的 workspace。

## 开工

开工成功立即创建可见的工作入口，准备与关联工单的管理见[工作与工单](../Missions/PRD.md#工作)。暂停、Stop、取消与人工介入在准备和执行阶段使用[统一执行控制](../Missions/PRD.md#执行控制)。取消的准备与工单退出活动 Worker 列表，历史保留。

讨论收敛后，用户点击右侧 Docs 底部的「开工」按钮，或直接对设计伙伴说“把 ABC 开工做掉”。两条入口都落到同一个动作 `work.start`，参数是当前会话、fork 点 turn 和一段可选的范围描述。聊天入口的调用与回复由[设计伙伴指令](../../../../packages/workbench/roles/design-partner.md)规定。

输入器为空时，「开工」直接登记请求，向准备分支发送配置的准备提示。有未发送内容时，同一按钮显示「发送并开工」，应用直接登记请求，将用户输入与准备提示合成准备分支的第一条消息，保留附件、技能引用及本次模型选择。按钮入口无需先让设计伙伴运行一轮；请求未成功接收时保留输入内容。

已有讨论从当前查看节点 fork 出准备分支，即使它是末端；所选节点仍在运行时，等待该 turn 结束再 fork。准备分支保留原角色指令，使用 `work-preparation.md` 配置的准备消息及本次范围。查看位置停在原节点，用户接着提问仍然延伸讨论线。新建会话直接以合成消息开始准备，无需先生成讨论 turn。

准备阶段产出相关设计提交、关联工单和所需的 worktree 登记，操作步骤由[开工准备指令](../../../../packages/workbench/roles/work-preparation.md)规定。开工入口不要求用户在弹窗里手选文件。一次开工拆出多张工单时，准备分支绑定第一张工单，其余的由调度器从准备轮末端 fork 出兄弟执行分支，合同作为首条消息。

开工与调度续跑不主动执行 compact，分支保留 fork 点之前的讨论上下文。

两种按钮入口均在准备轮结束后等待调度，排到工单时才注入 Worker 指令并执行；后续流程见 [工单](../Missions/PRD.md)。

设计伙伴改文档时知道自己 fork 出了哪些分支，会在回复里说明对哪张工单有影响；用户也可以直接切到 Worker 节点提问或纠正。文档提交对执行中工单的通知与续做规则见 [工单 · 流转](../Missions/PRD.md#流转)。

## 当前工作状态条

准备及工单执行分支的 composer 上方显示紧凑的“当前工作”状态条：工作名称、当前工单（如有）、实时阶段或等待原因、适用的主要操作和查看入口。准备未建单时也显示。较长原因与技术详情展开查看，取消放在更多菜单。完成后收为简短结果条，保留查看入口；普通讨论不显示执行控制。

状态条按当前查看分支的实际工作归属定位，不因继承的历史、角色文本或工单 id 推断归属。原讨论分支、普通 fork 不自动接管工作。查看执行分支历史节点时展示这份工作的实时状态；已迁移的旧分支显示“已转移到其他分支”和前往当前执行入口，不提供旧归属的执行控制。

操作明确标注范围：准备阶段为暂停准备或恢复准备，执行阶段为暂停本工单或恢复本工单自动推进；整份工作的批量操作在工作详情提供。没有活动轮次时仍可暂停、取消或恢复。人工接管显示推进方式及“恢复自动推进”，不把等待手动继续显示为正在运行。可用动作与禁用原因来自同一工作状态，切换节点、收起会话树或重启不改变执行状态。

在执行分支的已完成历史节点，状态条提供“从此处继续执行”，使用当前输入及发送配置转移执行并继续；普通发送仍按普通 fork 处理，入口明确区分，不隐式迁移工作。共享历史节点只按当前选定执行分支的归属操作；无法唯一确定归属时先选择目标工作。迁移行为见[执行控制](../Missions/PRD.md#执行控制)。

有待业务决策时，状态条显示问题和“回复此决策 / 普通消息”的明确发送模式；多张卡选择具体目标。答复的登记、送达和恢复规则见 [Inbox · 决策卡](../Inbox/PRD.md#决策卡)。回复目标为工作的当前执行分支，不因浏览历史节点而另开执行分支。模式、目标和输入在发送时固定，切换查看位置不改变已经提交的回复。

## 会话列表

新建会话旁的「全部」/ workspace 下拉只筛选会话列表，不切换当前阅读的会话，也不改变其他分页的 workspace 浏览范围。「全部」展示所有 workspace 的会话，不作为文档或角色的全局编辑范围。

会话列表在进入工作台时一次加载当前筛选范围内的全部会话树，不分页、不提供「加载更多」。此后会话的新建、活动、完成、归档和重命名只影响对应的列表行：其余行、已展开的子会话层次和滚动位置保持不变，列表不整体重建。当前打开的会话被打开或因自身活动上移时，列表滚动到该行可见；其他会话引起的重排不移动视口。

用户发起的会话树与冷启动的 agent 根会话统一展示，按最近更新时间排序，置顶的排最前。更新时间取整棵会话树各未归档分支中用户消息成功提交时间与 turn 完成时间的最新值；用户消息成功提交后立即刷新列表时间与排序，不等待 agent 完成，流式输出期间不推进更新时间。会话行的相对时间使用同一更新时间。会话行展示标题、状态、相对时间和适用的角色标记。All 筛选下，标题下方以副标题显示 workspace 名；选定具体 workspace 时隐藏该副标题。

一棵会话树在列表里只占一行（见「会话树」）；某个会话派出的 subagent 会话缩进挂在它下面。 包含子会话的会话入口左侧显示展开／折叠按钮，点击切换其下子会话的显示；默认折叠，没有子会话的入口不显示该按钮。折叠按钮不切换当前会话，点击会话行仍打开对应会话。

会话行左侧显示该行所属会话树的整体状态灯：进行中为黄色，已完成未读为绿色，已读不显示，颜色与「会话树」节点一致。同一棵树在列表中合并为一行时覆盖其全部成员分支；缩进挂出的 subagent 行显示自身会话树的状态。列表绿点表示该树有尚未确认的新完成内容，与树内节点的阅读状态分别记录。打开该树任意成员会话后，确认整棵树当时已有的完成内容，清除列表绿点；切到其他会话、重新加载历史或重启后，已确认的旧内容不再触发列表绿点。只有此后树内节点完成并产生新的未读内容时，列表才重新出现绿点；节点完成时已在当前可见阅读路径中展示的，不产生新的列表提醒。仅选中该树不持续清除后来其他分支产生的新提醒。同树内的节点跳转按「会话树」的节点阅读规则处理，不重复确认整棵树。打开父会话树不清除缩进 subagent 自身会话树的列表提醒。列表提醒的确认不将未查看路径上的节点标为已读，节点规则见「会话树」。

右键菜单：重命名、置顶/取消置顶、复制会话 id、复制内部会话 id、归档、刷新运行环境、重新连接、打开 rollout 文件。归档后从列表移除。

列表中任意会话都可以重命名，包括本轮未打开过的历史会话。重命名在弹窗中编辑当前标题，确认后列表立即显示新标题，重启后仍是新标题；取消或空白标题不改动标题。自动生成的标题只用于还没有标题的会话，不覆盖用户改过的名字。重命名不改变列表排序、置顶、归档状态与会话树结构，并提供同等的 CLI/RPC 调用路径。

## 会话历史刷新

每次进入和退出 Codex 会话时，尝试清理该会话可由 rollout 重建的历史数据库投影。重新进入时以当前 rollout 重建并展示历史，包含已落盘的中断轮次；外部修改 rollout 后，旧数据库投影与已加载内容不继续决定展示结果。

清理保留 rollout、会话元数据及必要的分支关系，不清空 Codex 状态数据库。清理失败不阻断会话进入或退出。浏览切换保持后台会话执行和输入草稿，已加载会话树内的历史节点跳转仍只改变查看位置。

## 搜索

新建会话下方放置搜索按钮，点击打开搜索弹窗。顶部输入关键词，下方左侧按「工单」「会话」「文档」分类展示结果，右侧预览选中匹配项附近的原文。两侧分别滚动并隐藏滚动条，浏览左侧时右侧保持可见。

工单搜索匹配标题与正文；会话搜索直接匹配属于 Vermillion 会话的 rollout 文件内容，不包含其他应用的会话；文档搜索匹配 `.vermillion/docs` 中的文本文件内容。

会话分类采用「会话树 → 匹配项」两层结构。会话树标题行显示与会话列表一致的标题和命中数量，支持折叠、展开。树下直接展示各匹配项的原文短摘取，并以清晰可辨的底色高亮关键词；不增加成员会话标题层，不以 rollout 文件名或 id 作为结果主标题。短摘取围绕命中位置保留可读上下文，超出显示范围时省略两端。

会话树按最近活动时间倒序排列；树内匹配项按所属成员会话的最近活动时间倒序聚拢，同一成员内按原文顺序排列。活动时间沿用[会话列表](#会话列表)的用户消息成功提交与轮次完成时间口径，树时间取成员活动时间的最新值。共享祖先中同一个位置被多个 fork 继承时只展示一次，独立位置的相同文字仍分别保留。

各分类初始最多展示 10 个顶层结果，会话分类以会话树计数；「展开更多」只展开当前分类。所有符合搜索范围的来源都参与扫描，展示数量或分批返回不终止后续来源的检索；未展示的结果可继续取得，不因先扫描的会话命中密集而永久遗漏其他会话。

单击匹配项选中并更新右侧预览，鼠标经过不改变选中项。右侧显示比左侧更大范围的纯文本原文上下文，以清晰底色高亮关键词，并将当前命中保持在可见位置；不加载真实会话，不渲染成聊天消息。

双击匹配项或使用打开动作进入对应对象：工单打开详情，文档打开编辑器并定位命中处，会话打开所属分支并定位到命中轮次。rollout 文件路径属于详情信息。

结果按批增量出现，不等全部来源扫完。扫描进行中弹窗保持可用，已出现的结果可选中和预览；后续结果到达不改变已选中的匹配项。底部显示扫描范围与耗时。关键词变化时立即放弃旧查询并停止它的扫描，新查询不排在旧查询之后；中文输入法未提交的中间内容不触发搜索。会话历史增长不改变这些行为。

搜索、后续结果获取与上下文预览同时提供 CLI 入口。

## 输入器

并行会话持续输出时，当前输入器保持响应。消息区只实时刷新当前查看路径中的内容；后台分支只通知运行、完成、失败、中断、审批及等待输入等状态，不因文本或命令输出持续刷新当前消息区。切到后台分支时展示已接收的完整内容，并实时更新该路径。切换到历史节点后，该节点之后的输出按后台内容处理。

每棵会话树缓存一份未发送草稿，包含文字、图片及其他附件和已选技能。同一棵树内切换节点或分支时保留这份内容；切到另一棵树时显示那棵树的缓存，首次进入且没有草稿时为空，切回后恢复原内容。新建会话使用独立草稿。切换工作台分页保留各份草稿；缓存作用于当前应用会话，不要求重启后恢复。

发送目标使用点击发送时的当前位置；发送队列按会话管理，执行配置遵循下述节点恢复规则。成功发送或加入发送队列后清空本次提交的草稿，不影响其他树或提交后新编辑的内容。图片的附件数据与预览跟随所属草稿保留，切节点、切分支、切树和历史刷新不清空图片；恢复后的图片仍可预览和发送。

移除 Attach files 按钮，保留现有拖拽与粘贴附件能力。

配置行保留 workspace 和引擎支持的模型、推理、速度选择。配置标签使用「模型」「推理」「速度」，标签和值同处一个控件内。字体与控件规格见 [UI/UX 规范](../../Foundation/UIUX/Standards.md)。

新建会话草稿态的模型、推理、速度以当前 workspace 的设计伙伴角色配置为默认值，未指定的字段沿用输入器上次选择，规则见 [角色与执行](../Roles/PRD.md)。用户可在发送前调整，创建会话与首条消息使用输入器当前显示的配置，后续消息也以当前选择发送。

应用为接入节点执行配置记录后新产生的轮次保存生效配置。切换到已完成且有执行记录的会话树节点时，输入器恢复该节点完成时使用的模型、推理档位与速度。共享历史节点使用原节点的执行记录，不受包含它的分支当前配置影响；记录在重新打开会话和重启应用后仍可读取。用户随后可手动调整，发送、创建分支及待发送节点转为正式节点的过程中保持本次提交的配置；手动调整不修改历史节点的执行记录。

不补齐接入前已有历史节点的执行配置，不将当前会话配置回填为历史执行记录。节点配置记录与恢复由 Vermillion 实现，不修改 Codex 引擎，也不解析 rollout 获取配置。分支选择与节点模型配置恢复分别管理，配置恢复不改变当前分支或角色身份。

已有会话的当前节点没有执行记录时，输入器先使用该会话已保存的发送配置；会话也没有已保存配置、而引擎在加载或恢复线程时报告当前执行配置时，以线程当前配置初始化后续发送。引擎报告的当前配置只补齐缺失的会话配置，不覆盖角色、用户选择或编排流程已经明确写入的会话配置；引擎级上次选择只用于仍无会话配置的情况。

## 会话树

首次进入会话时，树区域显示加载状态，完整会话树就绪后一次展示，再应用 Worker 显隐规则；不展示缺少祖先或分支的加载中间结果。消息区不等待整棵树就绪：打开会话后先展示当前查看位置所在路径的消息，树区域单独显示自己的加载状态；切到尚未加载的分支时只等待该分支所需的内容。加载期间其他界面保持可操作。已显示的会话树刷新时保留当前完整结构及其节点跳转能力，后台重新打开成员会话、刷新历史或准备分支转入 Worker 执行时，已显示的节点仍可浏览，不因加载状态失效报为未知节点。新快照就绪后整体替换，保留仍有效的选中节点与查看位置；不同会话之间不展示上一会话的树。加载失败明确提示原因，保留已显示的完整树及其浏览能力，不把残缺树作为成功结果，也不无限停留在加载状态。

会话树是 wrapper 侧的概念：一组发源于同一个会话的 fork 会话构成一棵树，每个分支对应 engine 中一个独立的线性会话，engine 只需要提供「从某个 turn fork」的能力。wrapper 记录树与成员会话的关系：树 id、成员会话 id、父会话 id、fork 点 turn id。fork 出的会话保留原 turn id，因此 turn id 是树节点的标识，树结构由各成员会话的 turn 序列推出：同一会话内相邻 turn 相连，fork 会话的第一个自有 turn 挂在 fork 点 turn 下面。

节点图默认隐藏 Worker 分支。图下方列表展示这棵树中仍在运行的 Worker，包括未结束的准备，以及排队、执行、等待合入、等待用户、暂停和人工接管的工单；点击后跳到该 Worker 分支的最新节点，并临时显示该分支及连接它所需的祖先节点。切到其他分支后，未选中的 Worker 分支重新隐藏。双击图中节点跳到该位置。

会话树提供「显示全部 Worker」开关，默认关闭。打开后显示这棵树包含的全部 Worker 分支，包括已结束的分支；关闭后恢复仅显示当前选中 Worker 的规则。Worker 自有节点显示 W，继承的讨论节点仍使用普通节点样式。

节点右键菜单提供「复制 session id」「复制内部 session id」「Open rollout」「删除分支」。复制的 ID 属于被右键点击节点所在的会话：session id 是引擎会话 ID，内部 session id 是 Vermillion 的会话 ID。「Open rollout」打开同一节点所属会话的 rollout 文件，沿用会话列表的打开方式，不改变当前查看位置；节点目标解析与打开提供同等 CLI/RPC 调用路径。

「删除分支」仅对会话树末端的 fork 会话节点可用，按完整会话树判断末端，不受 Worker 显隐影响。Vermillion 按所属会话持久化分支隐藏标记，从会话树移除该分支独有的尾部；其他可见分支仍然使用的共享祖先与分叉点保留。刷新、重新进入和重启后保持隐藏，成功发送留下的占位节点也不重新出现。删除当前查看的分支后，查看位置回到保留的共享祖先。

分支隐藏只影响 Vermillion 的会话树展示，不归档或回退引擎会话，不修改 rollout，不改变模型上下文及 fork 的祖先依赖。历史仍通过引擎接口读取，隐藏标记与会话归档状态分别保存；CLI/RPC 与节点菜单使用同一操作。隐藏的分支不参与会话行的更新时间、状态灯与未读聚合。

所有节点统一使用状态颜色：进行中为黄色，已完成未读为绿色，已读为中性色。当前查看位置用独立轮廓标记，不覆盖状态颜色。未读按节点记录，查看当前路径会将其中已完成的节点标为已读，不会清除其他分支或尚未查看的后续节点；运行中查看过的节点在完成后仍按当时是否展示判断已读状态。

跳转只改变查看位置，已加载树中的跳转不向 engine 发请求，运行中的分支不受影响。每棵树记住上次查看的位置，重新打开时回到那里。

当前位置同时标识会话分支与 turn。消息区显示从根到该 turn 的内容，之后的内容隐藏。点击其他分支节点时切换到该节点所属分支；准备与执行分支的活动不改变当前讨论来源。

普通 fork 保留对话上下文和模型配置，不继承开工请求、工单与执行动作的归属；继续原工作使用[当前工作状态条](#当前工作状态条)的专门入口。准备或 Worker 分支由调度器明确登记；会话树只对实际登记的执行会话应用 Worker 隐藏及状态规则，普通讨论不随相关工单结束而隐藏。

在当前位置追加提问：位置是所在会话的末尾时直接发送；否则从该 turn fork 出新会话再发送，新会话成为当前位置。fork 点不能是进行中的 turn。多个分支可以同时运行：在一个节点提问后切到另一个节点提问，两条分支各自跑各自的 turn。

非末端节点的提问提交后，ChatTree 立即在提交位置下新增并选中一个虚态子节点，消息区展示刚提交的待发送消息，同时释放输入框。“正在创建分支”是该虚态节点的状态提示。fork、加载新会话和发送在后台完成，不阻塞浏览、切换节点或在其他节点提问。fork 完成后虚态节点原位转为正式节点，随后正常展示回复。待发送消息绑定提交时的节点、内容、附件及发送配置；用户已切换查看位置时不自动跳回。失败时在该消息上显示原因并可重试，保留消息内容。

选中正在创建或发送的虚态节点时，Stop 取消该节点的整次分支发送操作；虚态节点右键提供「取消发送」，失败节点提供「移除」。取消或移除后占位节点退出会话树，已创建但尚无本次正式 turn 的空分支归档；后台 fork 或加载稍后返回也不继续发送、不恢复占位节点。清理失败明确反馈原因并可再次清理。

取消或移除保留本次消息的文字、附件和发送配置，供恢复到输入器重新编辑；不覆盖输入器中已有的新草稿。当前仍选中被移除的虚态节点时回到提交位置，已切换到其他节点时保持查看位置。其他分支的运行和待发送操作不受影响。

发送已被引擎接受并产生正式 turn 时，Stop 中断该 turn，保留正式节点与消息历史，按正式分支规则删除；取消与发送受理交错时也按是否已产生正式 turn 收尾，不把已有消息的分支当作空分支归档。成功发送的操作在正式节点接管后退出占位投影。

实现方向：将创建分支并发送作为独立异步操作，统一管理创建、发送、取消与收尾。前端收到受理结果即可结束提交状态，通过事件更新操作进度和新分支；提交、重试、取消及移除提供同等 CLI 调用路径。

## 图片预览

消息和输入器中的图片点开后，在预览图片上右键提供「复制图片」，将图片本身写入系统剪贴板，可粘贴回输入器或其他支持图片的应用。复制后保持预览打开；失败时显示原因。图片复制能力提供可命令行调用的入口，与界面使用同一实现。

## 消息中的文件链接

消息里的本地文件链接按「路径 + 可选位置」解析：末尾整体匹配 `:397`、`:10-11`、`:12:5`、`#L42`、`#L42-L50` 时视为文件上的位置，不参与打开；末尾不构成位置时，整串按路径处理。

`#` 后面不是行号时按路径原样处理，不剥离文档锚点。

盘符路径前面多写一个斜杠（`/I:/…`）按盘符路径处理。

点击用默认编辑器打开该文件，位置不参与打开。悬浮显示完整目标：绝对路径，带位置或不带。右键菜单提供「复制路径」和「复制文件位置」，复制成功后给出提示。

打不开或无法定位的目标（文件不存在、相对路径、锚点）原样显示目标本身与失败原因，并可以右键复制，不留下一个看不出指向哪里的链接。

## 消息中的文件变更

一轮改了文件时，消息下方列出变更：文件数与增删行数、可撤销本轮改动，每行一个文件（变更类型、相对 workspace 的路径、增删行数），点击打开 Diff 弹窗，见 [Diff 弹窗](../../Interaction/DiffViewer/PRD.md)。

## 消息中的工单

消息里出现的工单 id 渲染成工单标记，点击进入工作台 → 工作并定位工单详情，见 [工单](../Missions/PRD.md)。用户与 agent 会话使用相同行为。

## 消息中的会话导航

Agent 建议用户前往其他会话继续讨论时，可调用工作台 CLI，在发起调用的当前会话消息区插入“前往会话”组件。组件展示目标会话标题、角色及可选的简短前往原因，点击即可打开目标会话。组件随所在消息保留，再次打开来源会话时仍可使用。

所有目标都进入工作台 → 会话：会话树成员切到对应节点，冷启动的 agent 会话直接选中目标。导航同步目标所属 workspace，用户可直接阅读和继续对话。

工作台向 agent 上下文注入当前会话的 `sessionId` 和所属 `workspaceId`，工单上下文直接提供来源设计会话和执行分支的会话 ID。Agent 使用已提供的 ID 创建导航组件，无需先查询目标会话。CLI 创建导航组件时显式传入来源 `sessionId` 和目标会话 ID。

## 管理

工作台 → 管理 展示标题栏选择的 workspace 的根路径，提供「移除 workspace」按钮。移除前弹窗确认，确认后从工作台注销该 workspace，不删除磁盘文件。

## 桌面提醒

窗口不在前台时才弹桌面提醒，两种情况：自己的会话完成一轮；Inbox 出现新的决策卡或已合入通知。agent 会话完成不提醒。
