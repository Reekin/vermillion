# 思考

思考是主页，用于与设计伙伴讨论需求并修改文档。

点击 New Chat 进入草稿态，在输入器选择 workspace（默认上次使用的），发送首条消息时创建会话。

## 模式

输入器里 workspace 选择旁边有模式选择：发单 / 现做，默认发单，选定后在这棵会话树里保持，每条消息按发出时的模式处理。发单模式下设计伙伴只改文档、建工单，代码改动交给 Worker；现做模式下它在 workspace 根直接改代码、跑命令、做发布部署，做完后把文档改到与代码一致并提交 commit。同一棵树里可以在不同分支上混用两种模式。模式由工作台随每轮注入给设计伙伴，不出现在用户消息正文里。

## 会话列表

会话行只展示标题、状态与相对时间，不逐行显示 workspace 名；按 workspace 分组时保留分组标题。[用户：会话栏里这个vermillion是多余的]

只列用户自己发起的会话；管家、Worker、Supervisor 的会话在 Workspaces → 会话 查看。默认扁平展示，按最近 turn 完成时间排序，置顶的排最前，可切换按 workspace 分组。

一棵会话树在列表里只占一行（见「会话树」）；某个会话派出的 subagent 会话缩进挂在它下面。

每行前的状态灯：turn 进行中时闪动；turn 在会话未打开时完成则实心带光晕，打开后消失。

右键菜单：置顶/取消置顶、复制会话 id、复制内部会话 id、归档、刷新运行环境、重新连接、打开 rollout 文件。归档后从列表移除。

## 输入器

移除 Attach files 按钮，保留现有拖拽与粘贴附件能力。[用户：AttachFiles按钮去掉]

配置行保留 workspace、模式和引擎支持的模型、推理、速度选择。配置标签使用「模型」「推理」「速度」，标签和值同处一个控件内，使用相同字号，以中灰标签和明亮值区分层次。字体与控件规格见 [UI/UX 规范](../../Foundation/UIUX/Standards.md)，视觉见 [文字打样](../../Foundation/UIUX/Type-Sample.html)。

New Chat 草稿态的模型、推理、速度以当前 workspace 的设计伙伴角色配置为默认值，未指定的字段沿用输入器上次选择，规则见 [角色与执行](../Roles/PRD.md)。用户可在发送前调整，创建会话与首条消息使用输入器当前显示的配置，后续消息也以当前选择发送。

## 会话树

会话树是 wrapper 侧的概念：一组发源于同一个会话的 fork 会话构成一棵树，每个分支对应 engine 中一个独立的线性会话，engine 只需要提供「从某个 turn fork」的能力。wrapper 记录树与成员会话的关系：树 id、成员会话 id、父会话 id、fork 点 turn id。fork 出的会话保留原 turn id，因此 turn id 是树节点的标识，树结构由各成员会话的 turn 序列推出：同一会话内相邻 turn 相连，fork 会话的第一个自有 turn 挂在 fork 点 turn 下面。[用户：wrapper 侧就只需要额外记录会话树与各 fork 会话之间的关联关系，不再要求 engine 本身支持非线性会话能力，只需要支持「从某个 turn fork」的能力即可]

节点图列出树中全部 turn，标出当前位置和正在运行的末端。双击节点跳到该位置。跳转只改变查看位置，不向 engine 发任何请求，任何分支运行期间都可以随意跳转，运行中的分支不受影响。每棵树记住上次查看的位置，重新打开时回到那里。

当前位置是一个 turn。消息区显示从根到该 turn 的内容，该 turn 之后的内容隐藏 [用户：需要隐藏]。位于末端节点时对应唯一的线性会话；位于有分叉的节点时，任选一个包含该 turn 的成员会话读取（默认最近活跃的那条），读到的内容相同。

在当前位置追加提问：位置是所在会话的末尾时直接发送；否则从该 turn fork 出新会话再发送，新会话成为当前位置。fork 点不能是进行中的 turn。多个分支可以同时运行：在一个节点提问后切到另一个节点提问，两条分支各自跑各自的 turn。

## 消息中的文件变更

一轮改了文件时，消息下方列出变更：文件数与增删行数、可撤销本轮改动，每行一个文件（变更类型、相对 workspace 的路径、增删行数），点击打开 Diff 弹窗，见 [Diff 弹窗](../../Interaction/DiffViewer/PRD.md)。

## 消息中的工单

消息里出现的工单 id 渲染成工单标记，点击弹出工单面板，见 [任务与工单](../Missions/PRD.md)。所有会话（含 Workspaces → 会话 里阅读的 agent 会话）都一样。

## 消息中的会话导航

Agent 建议用户前往其他会话继续讨论时，可调用工作台 CLI，在发起调用的当前会话消息区插入“前往会话”组件。组件展示目标会话标题、角色及可选的简短前往原因，点击即可打开目标会话。组件随所在消息保留，再次打开来源会话时仍可使用。

目标为设计伙伴会话时，进入思考页并选中该会话；目标为管家、Worker 等工作台 agent 会话时，进入 Workspaces → 会话并选中目标。导航同步目标所属 workspace，用户可直接阅读和继续对话。

CLI 提供查询目标会话和创建导航组件的入口。Agent 能获取会话标识、标题、角色、所属 workspace，以及当前任务关联的设计伙伴和管家会话，据此选择具体目标；调用上下文能确定来源会话。管家、Worker 等角色说明包含这些入口的用法，在建议用户转往其他会话时提供可点击的导航组件。

## 右侧 Explorer

浏览和编辑当前 workspace 的 `.vermillion/docs`，通过底部按钮创建任务、补充任务或仅提交，见 [文档管理](../Documents/PRD.md)。一个会话可以创建多个任务，也可以给已有任务补充 revision。设计伙伴的职责与边界见 [角色与执行](../Roles/PRD.md)。

## 桌面提醒

窗口不在前台时才弹桌面提醒，两种情况：自己的会话完成一轮；Inbox 出现新的决策卡或已合入通知。agent 会话完成不提醒。
