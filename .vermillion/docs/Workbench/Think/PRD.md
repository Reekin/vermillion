# 工作台

工作台是主页，用于讨论需求、修改文档并查看执行。左侧会话列表常驻，右侧顶部依次为会话、工单、Docs、Domain、角色、Issues、Automation，默认打开会话。会话页包含 SessionPane 和 Docs Explorer；切换分页时保持挂载，保留查看位置与未发送草稿。其他分页使用标题栏的 workspace 选择器指定当前浏览和编辑范围。

点击 New Chat 进入草稿态，在输入器选择 workspace，发送首条消息时创建会话。列表筛选选中具体 workspace 时，新草稿使用它；All 下默认上次使用的 workspace。

## 开工

讨论收敛后，用户点击右侧 Docs 底部的「开工」按钮，或直接对设计伙伴说“把 ABC 开工做掉”。两条入口都落到同一个动作 `work.start`，参数是当前会话、fork 点 turn 和一段可选的范围描述；聊天入口由设计伙伴调用 CLI 完成，它自己只回一行已开工，不落文档、不建单。[用户：也可以发送一句“把讨论中的ABC开工做掉”]

输入器有未发送内容时，同一按钮显示「发送并开工」。点击后按当前查看位置发送输入内容、附件及明确的开工指令，设计伙伴通过 `work.start` 登记该需求；本轮结束后从包含该需求的节点派出 Worker。New Chat 中先创建会话，历史节点沿用分支发送规则，运行中的会话沿用输入器的追加或排队规则。发送失败保留输入，空输入时仍从当前节点直接开工。

`work.start` 登记一个待开工；当前 turn 结束后（没有进行中的 turn 就立即），工作台从该 turn fork 出准备分支，保留原角色指令，发送 `work-preparation.md` 配置的准备消息及本次范围。fork 点永远是讨论分支的这个节点，即使它是末端；查看位置停在原节点，用户接着提问仍然是延伸讨论线。

开工分支在第一轮里自己判断本次讨论涉及哪些文档改动，把它们提交为 docs commit（其余未提交改动留在工作区不动），判断是否需要 worktree，然后 `workItem.create` 建单并把自己登记为执行者，结束这一轮。范围不再由用户在弹窗里手选文件。[用户：也不再需要手动选择文档范围了，让agent自己判断本次需要纳入哪些文档变动] 一次开工拆出多张工单时，开工分支自己执行第一张，其余的由调度器从开工分支末端再 fork 出兄弟分支，合同作为首条消息。

开工与调度续跑不主动执行 compact，分支保留 fork 点之前的讨论上下文。[用户：不需要compact]

建单后的调度、执行、验证与合入见 [工单](../Missions/PRD.md)。

设计伙伴改文档时知道自己 fork 出了哪些分支，会在回复里说明对哪张工单有影响；用户也可以直接切到 Worker 节点提问或纠正。文档提交对执行中工单的通知与续做规则见 [工单 · 流转](../Missions/PRD.md#流转)。

## 会话列表

New Chat 旁的 All / workspace 下拉只筛选会话列表，不切换当前阅读的会话，也不改变其他分页的 workspace 浏览范围。All 展示所有 workspace 的会话，不作为文档或角色的全局编辑范围。

用户发起的会话树与冷启动的 agent 根会话统一展示，按最近 turn 完成时间排序，置顶的排最前。会话行展示标题、状态、相对时间和适用的角色标记，不逐行显示 workspace 名。

一棵会话树在列表里只占一行（见「会话树」）；某个会话派出的 subagent 会话缩进挂在它下面。

左侧会话标题不显示运行或未读状态灯；运行与已完成未读状态统一显示在会话树节点上。

右键菜单：置顶/取消置顶、复制会话 id、复制内部会话 id、归档、刷新运行环境、重新连接、打开 rollout 文件。归档后从列表移除。

## 输入器

工作台会话页保留同一份未发送草稿。切换会话树、树内节点或工作台分页时，文字、附件和已选技能随输入器保留，发送目标使用点击发送时的当前位置；发送队列与执行配置仍按会话管理。成功发送或加入发送队列后清空本次输入。

移除 Attach files 按钮，保留现有拖拽与粘贴附件能力。[用户：AttachFiles按钮去掉]

配置行保留 workspace 和引擎支持的模型、推理、速度选择。配置标签使用「模型」「推理」「速度」，标签和值同处一个控件内。字体与控件规格见 [UI/UX 规范](../../Foundation/UIUX/Standards.md)。

New Chat 草稿态的模型、推理、速度以当前 workspace 的设计伙伴角色配置为默认值，未指定的字段沿用输入器上次选择，规则见 [角色与执行](../Roles/PRD.md)。用户可在发送前调整，创建会话与首条消息使用输入器当前显示的配置，后续消息也以当前选择发送。

## 会话树

会话树是 wrapper 侧的概念：一组发源于同一个会话的 fork 会话构成一棵树，每个分支对应 engine 中一个独立的线性会话，engine 只需要提供「从某个 turn fork」的能力。wrapper 记录树与成员会话的关系：树 id、成员会话 id、父会话 id、fork 点 turn id。fork 出的会话保留原 turn id，因此 turn id 是树节点的标识，树结构由各成员会话的 turn 序列推出：同一会话内相邻 turn 相连，fork 会话的第一个自有 turn 挂在 fork 点 turn 下面。[用户：wrapper 侧就只需要额外记录会话树与各 fork 会话之间的关联关系，不再要求 engine 本身支持非线性会话能力，只需要支持「从某个 turn fork」的能力即可]

节点图默认隐藏 Worker 分支。图下方列表展示这棵树中仍在运行的 Worker，包括准备、排队、执行、等待合入和等待用户的工单；点击后跳到该 Worker 分支的最新节点，并临时显示该分支及连接它所需的祖先节点。切到其他分支后，未选中的 Worker 分支重新隐藏。双击图中节点跳到该位置。

会话树提供「显示全部 Worker」开关，默认关闭。打开后显示这棵树包含的全部 Worker 分支，包括已结束的分支；关闭后恢复仅显示当前选中 Worker 的规则。Worker 自有节点显示 W，继承的讨论节点仍使用普通节点样式。

所有节点统一使用状态颜色：进行中为黄色，已完成未读为绿色，已读为中性色。当前查看位置用独立轮廓标记，不覆盖状态颜色。未读按节点记录，查看当前路径会将其中已完成的节点标为已读，不会清除其他分支或尚未查看的后续节点；运行中查看过的节点在完成后仍按当时是否展示判断已读状态。

跳转只改变查看位置，已加载树中的跳转不向 engine 发请求，运行中的分支不受影响。每棵树记住上次查看的位置，重新打开时回到那里。

当前位置是一个 turn。消息区显示从根到该 turn 的内容，该 turn 之后的内容隐藏 [用户：需要隐藏]。位于末端节点时对应唯一的线性会话；位于有分叉的节点时，任选一个包含该 turn 的成员会话读取（默认最近活跃的那条），读到的内容相同。

在当前位置追加提问：位置是所在会话的末尾时直接发送；否则从该 turn fork 出新会话再发送，新会话成为当前位置。fork 点不能是进行中的 turn。多个分支可以同时运行：在一个节点提问后切到另一个节点提问，两条分支各自跑各自的 turn。

非末端节点的提问提交后，ChatTree 立即在提交位置下新增并选中一个虚态子节点，消息区展示刚提交的待发送消息，同时释放输入框。“正在创建分支”是该虚态节点的状态提示。fork、加载新会话和发送在后台完成，不阻塞浏览、切换节点或在其他节点提问。fork 完成后虚态节点原位转为正式节点，随后正常展示回复。待发送消息绑定提交时的节点、内容、附件及发送配置；用户已切换查看位置时不自动跳回。失败时在该消息上显示原因并可重试，保留消息内容。

实现方向：将创建分支并发送作为独立异步操作，前端收到受理结果即可结束提交状态，通过事件更新操作进度和新分支；同一操作提供 CLI 调用路径。

## 消息中的文件变更

一轮改了文件时，消息下方列出变更：文件数与增删行数、可撤销本轮改动，每行一个文件（变更类型、相对 workspace 的路径、增删行数），点击打开 Diff 弹窗，见 [Diff 弹窗](../../Interaction/DiffViewer/PRD.md)。

## 消息中的工单

消息里出现的工单 id 渲染成工单标记，点击进入工作台 → 工单并定位详情，见 [工单](../Missions/PRD.md)。用户与 agent 会话使用相同行为。

## 消息中的会话导航

Agent 建议用户前往其他会话继续讨论时，可调用工作台 CLI，在发起调用的当前会话消息区插入“前往会话”组件。组件展示目标会话标题、角色及可选的简短前往原因，点击即可打开目标会话。组件随所在消息保留，再次打开来源会话时仍可使用。

所有目标都进入工作台 → 会话：会话树成员切到对应节点，冷启动的 agent 会话直接选中目标。导航同步目标所属 workspace，用户可直接阅读和继续对话。

工作台向 agent 上下文注入当前会话的 `sessionId` 和所属 `workspaceId`，工单上下文直接提供来源设计会话和执行分支的会话 ID。Agent 使用已提供的 ID 创建导航组件，无需先查询目标会话。CLI 创建导航组件时显式传入来源 `sessionId` 和目标会话 ID。

## 右侧 Explorer

浏览和编辑当前 workspace 的 `.vermillion/docs`，见 [文档管理](../Documents/PRD.md)。设计伙伴的职责与边界见 [角色与执行](../Roles/PRD.md)。

## 桌面提醒

窗口不在前台时才弹桌面提醒，两种情况：自己的会话完成一轮；Inbox 出现新的决策卡或已合入通知。agent 会话完成不提醒。
