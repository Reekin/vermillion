# 任务与工单

## 任务

Mission 是一项工作目标及其文档 revision 序列，状态为进行中、已完成、已取消。从提交弹窗以「新任务」创建，或以「补充到现有任务」追加 revision；「仅提交」只保存文档，不产生任务也不触发处理。

任务看板在 Workspaces → 任务：展示任务及其工单，能查看状态、证据并进入对应 agent 会话；以弹窗快速查看时只列进行中的任务和未关闭的独立工单，并提示还有多少已结束项；展开为页面后显示全部。调度开关、并发上限与 Worker 运行记录也在这里。

## 工单

WorkItem 是可独立执行和验收的单位，来自管家拆单，或由设计伙伴为打包、测试等操作请求直接创建（独立工单，无 Mission、无需求引用，在 workspace 根执行，仍适用相关执行规范）。

工单主体是对文档的引用（路径、段落、commit），不另存需求副本。自身保存标题、范围与允许路径、验收条目、所需资源、依赖的工单、运行记录、证据、review 处置和决策。验收条目只描述做完后能观察到什么，不规定验收方法。

风险等级：R0 只读、R1 可丢弃制品、R2 项目内可回滚、R3 有限共享影响、R4 高影响。R0/R1 验收通过后自动关闭，其余进入 Inbox。

## 流转

排队中 → 进行中 → 待验收 → 已关闭；已取消是另一个终态。需要用户决定时进入待决策，答复后重新排队，只挂起相关工单。

调度器按 workspace 并发上限和资源需求取单，默认并发 2；同一资源（如 browser）不能同时分配给多张工单；依赖的工单全部关闭后才取。待决策和待验收的工单不占并发。工单连续三次没有走到提交（会话异常结束、Supervisor 中断、多轮无进展等）后不再自动重派，改为进入待决策：决策卡说明最近一次失败原因，选项是再试一次（计数清零）或取消工单。

Worker 提交证据、review 处置和验收报告。用户通过后，工作台合并分支并清理 worktree；打回后记录原因再排队；不做则取消并回收资源。项目代码重构不因名为“内部工作”就自动免除用户验收。

进行中改变方向时，管家通过工单更新调整目标、范围或验收并说明原因，Worker 立即收到；在调整送达那一轮里发出的提交视为依据旧合同而作废。取消工单则中断执行；被取消工单的依赖方交由管家判断处置。审阅者不能自行新增验收要求。
