# 工作与工单

WorkItem 是可独立执行和验收的单位，由开工分支创建（见 [工作台 · 开工](../Think/PRD.md)），或由用户在 工作台 → 工作 页手动创建（引用手改的文档或 Issue，冷启动一个 Worker）。允许路径限定代码修改范围；是否使用 worktree 由 Worker 根据项目和本次工作判断，需要时自行创建并登记目录与分支，否则在 workspace 根执行。

工单主体是对文档的引用（路径、段落、commit），不另存需求副本。自身保存标题、范围与允许路径、验收条目、所需资源、依赖的工单、来源设计会话与执行会话、运行记录、证据、review 处置和决策。验收条目只描述做完后能观察到什么，不规定验收方法；每条一到两个短句，先说从哪进、再说看到什么。证据摘要面向用户，只说改动后能看到的行为变化；commit、分支、测试命令、review 和验收过程记在证据的命令与附件里，不写进摘要。

风险等级：R0 只读、R1 可丢弃制品、R2 项目内可回滚。影响共享环境的操作（发布、部署、推送远端等）不建工单，由用户在工作台会话页和设计伙伴一起完成。

## 引用定位

工单引用由文件路径、固定 commit、可选段落定位与独立的说明组成。段落定位使用文档实际标题；同名标题用完整祖先标题路径区分。定位不包含自由描述或行号，说明不参与变化判断；省略段落定位表示引用全文。

创建工单或更新 refs 时，工作台在指定 commit 上校验文件与段落可以唯一定位，无法定位时指出具体引用并拒绝该次写入。已保存引用无法定位时明确报告，不静默按全文处理。标题被删除或更名属于原引用范围的变化，须报告定位失效并由合同更新确认新位置，不自动猜测替代标题。

文档合入按每条引用的实际范围判断：范围外变化不升级合同、不发送文档变更通知、不更新该条引用 commit；范围内变化只更新对应引用并发送相关差异。同文件中未变化的其他引用保留原 commit。通知与合同更新遵循[执行循环规范](Standards.md#执行消息)。

## 工作

工作覆盖一次开工从准备到交付的全过程。work.start 接收成功即产生可查询、可管理的工作，名称取开工范围或来源会话标题，准备期间可完善。准备请求承载这份工作，不提前创建空工单。一份工作包含一次准备及其产生的多张独立工单；准备完成后仍保留工作入口、来源、准备结果和关联工单。手动创建及领域自动创建的独立工单直接管理，不补造准备阶段。

工单阶段与会话运行事实分别表达。主流程为准备、排队、执行、待合入、已关闭，取消为另一结束结果；暂停、待用户决定和阻塞原因附着于当前阶段，不建立人工接管模式。处于执行阶段不代表 Agent 此刻正在运行；界面同时提供轮次是否运行、已停止或状态未确认等事实。程序派发的实际占用在确认停止后释放。

准备完成结果明确关联本次全部工单及其文档依据和所需目录登记，工作台核对交接结果后等待准备轮退出，再开放工单执行。单纯轮次正常结束或已经出现一张工单不代表准备完成。准备被暂停或取消时，不因已有部分工单而提前派发。准备完成后的各张工单独立推进，按各自依赖取单。

工作详情展示准备及工单的当前情况；全部工单结束后显示完成或含取消的结束结果，不把部分取消显示为全部交付。工作层提供暂停全部、恢复全部推进和取消剩余工作，只作用于未结束部分；单张工单操作只作用于本单，已完成成果与记录保留。准备中的操作目标为准备过程，进入工单执行分支后的目标为该工单。

## 看板

领域 Owner 可依照[自动修复授权](../Domains/PRD.md#自动修复授权)为 Issue 创建修复工单。工单关联来源 Issue、巡检会话和授权判断，进入相同的 Worker 调度、独立审阅及验收流程。

工作看板在 工作台 → 工作，展示当前 workspace 的全部工作及独立工单。顶部工具条提供自动推进开关、执行并发上限与执行中、等待中、已结束统计；统计按准备过程和独立执行工单计数，工作分组不重复计数。

看板按来源会话树分组，组标题使用会话列表中的树标题。同一会话树的多次开工、所属工单和有该树来源的独立工单放在同一组；没有来源会话树的条目归入「独立工单」。分组可展开收起，切页后保留展开状态；从工单链接进入时展开所属分组并定位目标。页面不使用「当前工作」作为集合分类。

组内每次开工保留一个可展开的工作条目，建单前显示准备情况，建单后在其下展示关联工单。同一来源的多次开工仍可分别查看和管理，每张工单只出现一次。工作名称使用开工范围，未填写时使用来源会话标题；长范围在列表中截断，完整内容可查看。工作条目只展示名称、工单数量、最近变动时间、当前状态与适用操作，不重复列出下方工单的标题或状态。准备记录与已取消记录保留可见。

信息层级为会话树、工作、工单。树标题承担分组，工作与工单用适度缩进区分，避免多层厚重卡片和重复标签。标题为主要信息，时间、数量和运行信息为辅助信息；次行只放具体等待原因或必要说明，不重复状态。参考[交互示意页](mock/workspaces.html)的间距与对齐，以及[窄窗口](mock/narrow.png)效果；分组、内容与操作以本文为准。

每张工单使用一致的行布局：风险标签、标题、运行信息（turn 数和最近变动时间）、状态、适用的暂停或恢复入口，以及固定的取消 × 和「会话」位。关联工单与独立工单的信息和操作一致。时间不依赖是否已有运行记录，始终显示。× 只在这一行 hover 时显示，但始终占位；状态、时间与操作列在各行对齐，没有会话时会话位留空。长中文标题不挤压状态和操作，窄窗口允许辅助信息换行，保持标题和操作可读可用。

工单处于等待时，状态使用具体阶段，例如「退回待续做」「合入受阻」「等待用户」，并在次行显示简短等待原因。「会话」跳到工单的执行会话：统一进入工作台 → 会话，fork 分支定位到对应节点，冷启动会话直接选中。工作层操作遵循[工作](#工作)，工单层操作只作用于本单；已结束的标题和状态适度降灰，仍保持可读。

排序采用「未结束在前、已结束在后 → 最近变动时间从近到远」。准备、执行、排队、等待用户、暂停及中断都属于未结束；已关闭和已取消属于已结束，不在未结束内部另设状态优先级。分组内有未结束内容时整组归入未结束，全部结束时归入已结束；组间按此规则排序，同一组始终连续，不因子项状态被拆散。组内工作及独立工单、工作内关联工单分别沿用同一排序规则。

工单变动时间使用工单最近更新时间；工作的变动时间取准备记录与关联工单更新时间的最大值；会话树分组的变动时间取组内工作与工单变动时间的最大值。页面显示的时间与排序口径一致，不以打开页面或读取记录的时间刷新排序；同一时间保持稳定顺序。状态或业务记录更新后重新排序并保留展开状态。标题栏的 workspace 选择器切换看板范围。

## 工单面板

工单有一个统一的详情面板，以弹窗打开。弹窗标题使用工单标题，首屏固定回答当前在做什么、为什么等待、下一步由谁处理、用户是否需要操作；风险、状态、工单 id 和时间作为辅助信息。「会话」进入执行会话，「来源」回到来源设计会话的 fork 点，滚动长内容时仍能直接使用。

当前进展按工单、执行动作、合入动作和运行记录的真实状态生成。等待时显示具体阶段、最近原因、当前处理者、恢复条件或下一步，以及已等待时长；无需用户操作时明确说明。提交被退回后展示退回原因、原 Worker 的实际运行情况和是否已收到续做要求，不把这些情况统一显示成「排队中」。失败信息使用可读摘要，展开后提供原始原因和阻塞文件；没有记录到的细节不推断。

当前进展下方是按时间排列的关键事件，默认显示最近事件，可展开完整历史。事件使用用户可理解的动作描述，覆盖开始执行、合同调整、提交验收、合入检查、退回及通知送达、恢复执行、合入完成；run id、内部 stage 和 `done` 等内部字段只出现在技术详情里。

其余材料按「任务要求」「验收结果」「审阅意见」「检查与附件」分组折叠。折叠标题给出目标、通过数、处置数等摘要；验收要求与对应结果成对展示，不在面板不同位置重复全文。空的依赖、决策、附件等区块不占据页面；待用户答复的决策提升到当前进展区并提供操作。工单关闭后，当前进展改为成果摘要、合入 commit 和验收结论，历史退回与失败保留在事件记录中。

会话消息里出现的工单 id（开工分支的合同、设计伙伴的回复、决策卡里的相关工单）不以裸 id 显示，渲染成一枚工单标记：风险标签、标题、状态胶囊，状态随工单实时变化。点击标记进入工作台 → 工作并定位工单详情。

## 流转

工单依照[工作](#工作)中的阶段流转。Worker 通过 CLI 登记业务进展、提出决策和提交成果；程序完成派发、条件校验与合入。自然语言回复和单个轮次结束不代替业务交接，暂停或等待期间保留阶段、成果、固定执行会话与 worktree。

自动推进默认开启，执行并发上限默认为 2；已有 workspace 沿用保存的开关和并发设置。准备和 Worker 的程序派发使用同一执行并发限制。并发限制不拦截普通会话聊天；程序派发与业务 CLI 按 workspace 并发上限和资源需求取单，`dependsOn` 全部关闭且 `needs` 声明的资源没有被执行中的工单占用才取。同一 workspace 内共享且不能同时操作的具体对象不能同时分配给多张工单；独立浏览器、桌面和验收实例可以并行，不因使用同类工具而互斥。`workItem.update` 支持调整 `needs`，调整后调度器按当前声明取单。前置工单被取消时，依赖它的工单保留当前阶段并显示等待用户处置依赖。

调度器排到工单时，先在执行会话追加 Worker 开发者指令并应用 Worker 模型配置，再把合同作为下一条消息送过去续跑；普通恢复不重复追加相同指令。没有来源会话的独立工单冷启动 Worker，合同作为首条消息。会话 cwd 始终保持 workspace 根目录；使用 worktree 时，Worker 在工具调用中显式指定对应工作目录或文件绝对路径。

Worker 在选定的工作目录完成开发、review 和冷验证。使用 worktree 时，提交前 rebase 到当前主分支；在 workspace 根执行时直接提交本次成果。工作台接收证据，默认自动合入，失败处置见[合入进度与处置](#合入进度与处置)；合入成功后立即关闭工单，Inbox 收到已合入通知，不等待 worktree 清理。纯操作工单及仅交付仓库外独立产物的工单通过验证后直接关闭，保留证据与产物位置，无需 Git 提交或合入。允许路径中的仓库外路径不参与 Git 成果检查；同时包含仓库内成果时，仓库内部分仍须完成提交检查与合入。用户在已合入通知上可以附理由回滚：工作台还原这次合并，原 Worker 带着理由续做。

worktree 清理由后台低频维护执行，默认每 5 分钟检查一次工作台登记的候选目录，不在工单刚结束时立即尝试删除。 Worker 的活动 turn 结束后先发出退订请求，不等待引擎立即卸载。维护只清理已不再使用且归属匹配的 worktree；排队、执行、待决策或续做仍需使用的目录均保留。目录被占用或清理失败时留待下一次检查，不重开工单、不占用 Worker 并发，也不产生清理决策卡。候选记录可跨进程重启保留，同一维护操作提供 CLI 入口。

需要改变尚未获准的需求、超出授权或存在必须由用户选择的取舍时，Worker 发决策卡并结束本轮，工单保留阶段并登记等待用户的事项；用户在决策卡或对应会话的决策回复模式中答复，交接规则见 [Inbox · 决策卡](../Inbox/PRD.md#决策卡)。能自行处理的技术问题继续处理，不因 review 或验证达到固定轮数而自动要求用户决定。分支与主分支代码冲突由 Worker 自己在 worktree rebase 解决后重交。

合同修订号只跟随交付物相关字段：objective、scope、acceptance 和 refs。调整 title、needs、dependsOn 不改变修订号，执行中的提交不因这些调整被拒。提交明确对应所依据的合同，工作台只接受符合当前合同的提交。读取最新合同并处理变更影响后可在当前轮提交；依据过期时保留成果与已有证据，要求更新依据及受影响的结果，不以轮次切换作为提交条件。

执行期间来自其他会话或用户的合同调整与引用文档合入，工作台立即送进执行会话。执行会话自己发起的合同调整与文档合入只落记录，不回送、不中断当前轮：Worker 通过 `workItem.update` 加入 dependsOn 后可以正常收尾本轮，��作台等该轮结束再按等待条件处理。业务通知关联合同调整、文档合入、提交退回或用户决定，按已登记内容交付一次；引用文档 diff 只出现在通知和执行历史里，不写入合同本体。`workItem.cancel` 中断执行会话，将已登记的 worktree 纳入后台清理候选，按上述维护规则回收。

### 合入进度与处置

工单在待合入阶段区分等待合入、正在合入、合入受阻和原 Worker 处理中。列表与详情显示实际进度、最近失败原因、阻塞文件及当前处理者，不显示自动重试倒计时。

程序对已通过提交检查的成果执行一次正常合入。失败保留成果与检查点，提供立即重试、交给原 Worker 和取消入口；监工在周期检查时读取相同事实。主工作区改动归属等需要用户判断的阻塞进入 Inbox，不能擅自提交、stash 或丢弃用户修改。

交给原 Worker 时保留固定会话，交付当前成果、失败原因和用户说明，返回实际交付结果或明确阻塞原因。仅写入排队状态不算交付成功，不创建人工接管模式。原 Worker 处理本单冲突、rebase 和受影响验证，最终主分支操作仍通过工作台串行入口；不重做未受影响的开发与验收。

合入、明确重试和回滚共用串行边界，同一合入动作不能同时执行两次。Worker 通过 CLI/RPC 登记处理结果，工作台核对实际 Git 结果后关闭工单。Git 已完成但记录尚未收尾时只补做登记，不重复合并。

### 执行、审阅与验证

执行与材料交接由 [Worker](../../../../packages/workbench/roles/worker.md)、[Reviewer](../../../../packages/workbench/roles/reviewer.md) 和 [Verifier](../../../../packages/workbench/roles/verifier.md) 指令规定。界面验收实例由工作台在独立桌面启动，不出现在用户操作屏幕上。

验证结果区分通过、发现缺陷、条件不足和未完成；条件不足与未完成不算产品缺陷，也不算通过。只有要求全部得到验证且符合文档终态时才能完成交付。有效的逐项观察和证据随续做保留，无关文档更新不使其失效；修复或需求变化只复核受影响部分。审阅与验证的交接、进度查询和续做由角色 prompt 规定。

### 执行控制

一张工单固定使用一个 Worker 会话。开工来源的设计讨论、Worker 会话和普通 fork 的聊天均复用普通会话的发送、追加、Stop 和继续能力；聊天不修改工单阶段，不登记人工接管，也不按消息文字推断业务动作。历史 fork 只用于讨论，不迁移工单；产品不提供从历史节点转移执行的入口。

工单不保存普通聊天的待发送队列，不提供工单专属撤回或消息受理确认流程。会话层的正常发送与确认能力保持，不能把工单的自动排队和恢复机制扩展到所有普通会话。

自动推进开关控制 workspace 的新准备、Worker 程序派发、监工自动检查和后台自动巡检。关闭后不启动新自动动作，已开始的轮次、合入和结果登记可以收尾；重新开启不解除用户明确暂停或未解决的业务等待。

工作和单张工单保留明确的暂停、恢复与取消操作。暂停阻止目标的新程序派发和监工处置，并中断目标当前业务执行，保留成果；整份工作暂停还停止监工的新检查轮。取消结束目标并保留历史。单张工单暂停不阻止监工检查同一工作中的其他工单。恢复使未结束目标重新具备推进条件，仍检查依赖、资源和业务等待。

普通 Stop 只中断当前会话轮次，不隐式暂停整份工作、不改工单阶段。用户主动停止的事实可查询，不能被自动派发或监工当成故障自行续做；用户在原会话继续，或明确恢复该任务后，才继续推进。

业务 CLI 校验当前工单、固定 Worker、用户暂停/取消及该动作所需的依赖与资源条件。派发、显式继续和合入操作不重复启动已有执行；已经在运行或动作不适用时返回当前事实。普通聊天不经过工单准入，业务 CLI 的校验不扩展为对所有 Agent 工具调用的限制。

### 运行失败与恢复

业务派发由已登记的新任务、明确继续、决策答复、合入转交或新业务通知发起一次。等待依赖或资源时保留该请求；实际派发失败后保留原因和未交付内容，等待用户或监工明确处置。剩余通知、失败记录、状态刷新和应用重启本身不重新授权同一批内容再次派发。准备与 Worker 的上述入口遵循相同规则。

准备、Worker 与合入失败保留阶段、成果、最近错误和可执行的下一步。轮次状态来自宿主和引擎，不把没有新消息或耗时较长直接判为失败；读取进度见[读取会话消息](../Roles/PRD.md#读取会话消息)。

Worker 轮次结束但没有提交或决策等交接时，工单保持未交付，显示会话已结束与缺少交接。程序不自动催办、不生成续跑提示、不安排多档失败重试。异常由监工在周期检查时判断，具体处置职责见角色指令。

准备未完成就中断时保留已有文档、工单与会话，提供明确的重试入口；完整交接前不创建监工。程序不因部分建单而推断准备完成。

应用重启读取工单及固定会话，核对实际轮次并展示当前事实；暂停、取消和用户主动停止保持有效。重启不因缺少内存跟踪而重新派发正在执行的工作，不把历史轮次结束推断为需要自动续跑。

### 监工

一次开工的完整工单清单已登记且准备轮结束后，程序从准备结束的 turn fork 一个监工会话并发起首次检查，与 Worker 派发共用同一交接依据。一份工作只创建一个监工，后续检查始终复用该会话；无准备过程的独立工单保留原有派发入口，不补造准备或监工。

仍有未结束工单且工作允许自动推进时，每次监工检查轮结束后等待 5 分钟，再发起下一轮。上一轮没有结束时只等待引擎结束通知，不追加检查消息、不另开 turn、不积攒检查次数。异常立即记录展示，但不触发额外的监工检查轮或待检查事件队列。

workspace 自动推进开关关闭期间保留原检查期限；重新开启时未到期继续等待，已到期只检查一次，不补跑关闭期间的次数。开关变化不重置上一轮结束后的五分钟周期。

整份工作暂停时不启动新的监工检查；恢复且自动推进已启用时检查一次，再恢复周期。全部关联工单关闭或取消后停止巡视，保留监工会话与记录。监工检查不占 Worker 程序派发的并发名额。

应用重启复用已登记监工会话，活动 turn 继续等待结束后计时；空闲会话按已有检查时间恢复周期，不重复 fork。监工本轮失败记录原因，空闲后仍使用同一周期，不增加专用退避策略或另一层监工。

工作详情可进入监工会话并查看最近检查、当前运行情况及下一次检查时间。程序向监工提供所属工作与工单的查询标识；监工的判断、动作与行为边界由[监工角色](../Roles/PRD.md#监工)定义。

### CLI

Worker 可通过 `asksource` 询问开单来源；会话消息读取和通用 `steer` 的行为见[会话读取与通信](../Roles/PRD.md#会话)。来源位置使用工单记录的设计会话与开单 turn。

工作与工单查询、准备完成登记、业务进展与依赖调整、提交成果、决策答复、明确暂停/恢复/取消、继续原 Worker、合入重试和结果登记均提供 CLI/RPC，与界面使用相同服务。操作返回实际结果和阻塞原因；程序派发或会话发送不可用时，不把仅保存意图报告为执行成功。

诊断分别展示业务阶段、固定会话与真实运行状态、等待事项、依赖、程序派发开关、资源占用、成果及失败原因；工作诊断另展示监工会话与检查情况。普通聊天使用通用会话接口，不提供工单聊天队列、执行迁移或人工接管接口。CLI 帮助可查询单方法的参数、适用状态和示例。
