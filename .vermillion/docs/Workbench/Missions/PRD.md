# 工单

WorkItem 是可独立执行和验收的单位，由开工分支创建（见 [工作台 · 开工](../Think/PRD.md)），或由用户在 工作台 → 工单 页手动创建（引用手改的文档或 Issue，冷启动一个 Worker）。允许路径限定代码修改范围；是否使用 worktree 由 Worker 根据项目和本次工作判断，需要时自行创建并登记目录与分支，否则在 workspace 根执行。

工单主体是对文档的引用（路径、段落、commit），不另存需求副本。自身保存标题、范围与允许路径、验收条目、所需资源、依赖的工单、来源设计会话与执行会话、运行记录、证据、review 处置和决策。验收条目只描述做完后能观察到什么，不规定验收方法；每条一到两个短句，先说从哪进、再说看到什么。证据摘要面向用户，只说改动后能看到的行为变化；commit、分支、测试命令、review 和验收过程记在证据的命令与附件里，不写进摘要。

风险等级：R0 只读、R1 可丢弃制品、R2 项目内可回滚。影响共享环境的操作（发布、部署、推送远端等）不建工单，由用户在工作台会话页和设计伙伴一起完成。

## 看板

工单看板在 工作台 → 工单，默认列表用于快速看清工单、当前状态和进度。顶部一行工具条：调度开关、并发上限步进器、一句等宽统计（执行中 / 等待中 / 已结束的数量），没有说明文字。

工单按来源会话树分组：同一棵树开工产生的工单在一组，组头是树标题，可展开收起；手动创建的工单归在「独立工单」组。卡片、间距和信息分组参考[交互示意页](mock/workspaces.html)，包含[收起](mock/workspaces.png)、[展开](mock/expanded.png)、[悬停](mock/hover.png)和[窄窗口](mock/narrow.png)效果；业务内容与操作遵循本文。

每张工单一行：风险标签、标题、运行信息（等宽小字：turn 数、最近时间）、状态胶囊、然后是固定的两个位：取消 × 和「会话」。× 只在这一行 hover 时显示，但始终占位，所以「会话」与状态列在所有行里对齐；没有会话的工单会话位留空。等待用户的工单显示简短等待原因。「会话」跳到该工单的执行会话：统一进入工作台 → 会话，fork 分支定位到对应节点，冷启动会话直接选中。

看板显示当前浏览 workspace 的全部工单，已结束的标题和状态降灰。标题栏的 workspace 选择器切换看板范围。

## 工单面板

工单有一个统一的详情面板，以弹窗打开：标题、状态胶囊、风险标签、目标、范围与允许路径、验收条目、引用的文档、依赖的工单、运行记录、证据、决策；底部「会话」按钮跳到执行会话，「来源」按钮跳到来源设计会话的 fork 点。看板里点击工单行的标题打开这个面板。

会话消息里出现的工单 id（开工分支的合同、设计伙伴的回复、决策卡里的相关工单）不以裸 id 显示，渲染成一枚工单标记：风险标签、标题、状态胶囊，状态随工单实时变化。点击标记进入工作台 → 工单并定位详情。

## 流转

状态：准备中（开工分支正在落文档、建单）→ 排队 → 执行中 → 等待合入 → 已关闭；等待用户是挂起，已取消是另一个终态。等待用户的工单不占并发，保留成果、原会话与 worktree。

调度器默认开启，并发上限默认为 2；已有 workspace 沿用保存的开关和并发设置。调度器按 workspace 并发上限和资源需求取单，`dependsOn` 全部关闭且 `needs` 声明的资源没有被执行中的工单占用才取。同一 workspace 内共享且不能同时操作的具体对象不能同时分配给多张工单；独立浏览器、桌面和验收实例可以并行，不因使用同类工具而互斥。`workItem.update` 支持调整 `needs`，调整后调度器按当前声明取单。前置工单被取消时，依赖它的工单转为等待用户并说明原因。

调度器排到工单时，先在执行会话追加 Worker 开发者指令并应用 Worker 模型配置，再把合同作为下一条消息送过去续跑；普通恢复不重复追加相同指令。没有来源会话的独立工单冷启动 Worker，合同作为首条消息。会话 cwd 始终保持 workspace 根目录；使用 worktree 时，Worker 在工具调用中显式指定对应工作目录或文件绝对路径。

Worker 在选定的工作目录完成开发、review 和冷验证。使用 worktree 时，提交前 rebase 到当前主分支；在 workspace 根执行时直接提交本次成果。工作台接收证据并执行合入；合入成功后立即关闭工单，Inbox 收到已合入通知，不等待 worktree 清理。纯操作工单通过验证后直接关闭。用户在已合入通知上可以附理由回滚：工作台还原这次合并，原 Worker 带着理由续做。

worktree 清理由后台低频维护执行，默认每 5 分钟检查一次工作台登记的候选目录，不在工单刚结束时立即尝试删除。 Worker 的活动 turn 结束后先发出退订请求，不等待引擎立即卸载。维护只清理已不再使用且归属匹配的 worktree；排队、执行、待决策或续做仍需使用的目录均保留。目录被占用或清理失败时留待下一次检查，不重开工单、不占用 Worker 并发，也不产生清理决策卡。候选记录可跨进程重启保留，同一维护操作提供 CLI 入口。

review 或冷验证两轮不过、合入时主工作区状态阻挡、发现文档与代码现状冲突、超出授权需要用户取舍时，Worker 发决策卡并结束本轮，工单转为等待用户；用户在决策卡上答复，或直接切到该分支说明，Worker 续做。分支与主分支代码冲突由 Worker 自己在 worktree rebase 解决后重交。

Worker 执行期间引用的文档有新提交时，工作台把 diff 作为下一条消息送进执行会话；送达时正在跑的那一轮提交视为依据旧文档作废（工单回排队、丢弃 evidence、保留 worktree），下一轮按新文档续做。`workItem.update` 调整合同同样立即送达。`workItem.cancel` 中断执行会话，将已登记的 worktree 纳入后台清理候选，按上述维护规则回收。

### 执行、审阅与验证

Worker 开始执行前重新读取涉及的代码，不信任讨论里对代码现状的描述。只许少做，不许多做；不读其他工单的 worktree。

Worker 自行邀请 reviewer，判断哪些意见适用；review 最多两轮。随后由空白 subagent 只按文档终态和验收条目验证真实结果，不看讨论内容。验收方法按改动性质选择；涉及界面时通过工作台起一个独立桌面上的实例，用户屏幕上不会出现，实例的 CDP 地址由 Worker 提供。

### 运行失败与恢复

从创建 worktree、打开会话、发送消息到执行与合入，各阶段失败都进入可查询的运行记录，不仅打印日志。进程仍在运行工具或等待模型输出时，不仅因耗时长判为失败。

运行异常时恢复原执行会话，失败原因作为下一条消息送达。每张工单最多自动重试 4 次，间隔 1、5、30、300 分钟；第 5 次失败后转为等待用户，发决策卡展示最近原因和已尝试的恢复，允许再试或取消。重试从原会话继续并清零计数。 连续多轮没有提交由 `maxIdleTurns` 判定，先在原会话要求提交或说明，仍无进展则记一次失败。

工作台启动时核对持久化进度与运行时状态：原会话仍有活动轮次时继续跟踪，空闲且工单仍需续做时发送恢复消息；打不开的记一次失败、工单回排队。用户交谈、轮次交接与后台续接遵循[执行循环规范](Standards.md#轮次与恢复)。

### CLI

所有动作都有 CLI/RPC 入口，与自动调度共用状态判断：`work.start`、`workItem.create / update / submit / cancel / diagnose`、`decision.create / answer`。命令返回实际结果、当前等待原因和合法下一步；桌面调度器不在线时明确说明记录已保存、尚未派发。`workItem.diagnose` 汇总当前阶段、等待原因、执行会话、依赖、调度开关、资源占用、最近失败和下次重试。CLI 帮助可查询单个方法的参数、适用状态和示例。

## 规划能力

### 暂离（尚未实现）

暂离用于睡觉等用户离开期间，由一个 agent 低频巡视所有未结束的工单，发现执行卡住或无人推进的情况并汇报到 Inbox，不代替用户处置。巡视间隔支持半小时、一小时。
