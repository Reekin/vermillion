# 执行循环规范

## 开发准备与检查

开发依赖使用项目声明的包管理器和锁文件，依赖准备不影响用户正在使用的实例。

检查范围由改动实际影响决定，默认运行相关检查；跨包影响需要扩大时才运行相应的整体检查。角色、仓库操作说明和工单使用一致规则，不机械要求每个参与者重复全量套件。已有检查证据对应的代码未受影响时可复用；产品行为要求和真实用户路径验证不因缩小检查范围而删减。

## 执行模型

执行模型围绕工单、当前动作和等待条件组织。问题只有两个去向：Worker 自己续做，或转为等待用户；不增加中间 agent 和独立调度循环。

`needs` 只声明共享且不能同时操作的具体对象，同一对象使用同一资源名。独立实例不声明资源，工具类别 `browser`、`desktop` 不作为互斥资源名；前置工单只用 `dependsOn` 表达。资源声明不提供跨 workspace 互斥保证。

调度、CLI/RPC 与角色指令使用同一套状态和恢复规则；状态所有权、事务和事件顺序统一遵循[架构](../../Foundation/Architecture.md#持久化与事务)。

运行记录格式不受支持时明确报错并停止该工作区的执行，不忽略记录或把已有工作当作新任务派发。存量数据转换与正常调度分开，转换前结束持有这些记录的运行实例。

等待必须有可查询的原因和恢复条件；重试续接未完成动作，保留原会话与成果，不重复已完成的外部操作。

## 轮次与恢复

用户主动停止与运行异常分别处理：开工准备阶段主动停止持久化为取消，终止该请求及尚未执行的关联工单；正式执行阶段主动停止保留可查询、持久化的暂停原因，只有用户明确恢复才解除暂停。自动重试与后台恢复不得解除取消或暂停。

工单的会话归属跨轮次保持，用户直接进入 Worker 会话发起或追加消息仍沿用该归属。调度器跟踪用户与调度器发起的实际轮次，不因用户交谈重复派工或中断执行，普通进度问答不计为未提交失败。

轮次结束只结算所属执行，旧轮收尾不能释放新轮归属或修改新轮动作。提交被退回后保留成果，等待提交所在 turn 结束并完成调度收尾，再启动下一轮；用户已启动新轮时跟踪该轮。已有续做安排时不额外发送未提交催办。

后台连接保留活动 turn，不隐含中断或强制重载。续做指令在空闲时开启新轮，执行中的工单调整追加到当前轮；引擎明确拒绝追加且确认原轮结束时，将尚未送达的消息交给下一轮。消息送达以引擎应答为准，展示投影不能单独决定执行是否活跃，正常轮次结束不计为送达重试失败。

## 执行消息

会话读取与通信复用现有引擎和会话定位边界；`asksource` 等待模型答复时不持有工单或 workspace 事务锁。临时询问 fork 的归档在收尾路径执行，归档结果与答复结果分别报告。产品行为见[角色与执行](../Roles/PRD.md#会话)。

首次派工提供完整执行说明；同一会话后续消息只携带本次增量，不重复身份、工作目录规则、历史记录和通用提交要求。

决策答复包含对应问题、所选选项、用户备注，以及等待期间尚未告知的工单调整。引用文档提交通知包含提交 SHA、相关文档 diff 和重新读取最新工单后继续的指令。同一消息内每项答复或调整只出现一次，历史记录保留供查询。

## 状态与回收

语义判断由 Worker 完成，程序负责确定性状态转换与动作约束。自动合入、Agent 接管期间的主分支写操作与回滚共用工作台的串行边界；跨模型轮次的等待不占住服务事务锁。接管归属持久化，调度器和 Agent 不并发执行同一合入，完成登记核对实际 Git 结果。业务行为见[合入进度与处置](PRD.md#合入进度与处置)。

工单完成、会话历史和目录回收相互独立。目录归属与使用状态以回收时的记录为准，登记、复用与回收遵守同一串行边界。退订应答不等于执行环境已经卸载，目录占用不阻塞工单结束。回收行为见[工单](PRD.md#流转)，历史读取与执行环境边界见[架构](../../Foundation/Architecture.md#会话与执行环境)。

工单状态、提交与恢复行为见[工单](PRD.md)，决策与结果展示见[Inbox](../Inbox/PRD.md)。
