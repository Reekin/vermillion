# 执行循环规范

## 开发准备与检查

开发依赖使用项目声明的包管理器和锁文件，依赖准备不影响用户正在使用的实例。

检查范围由改动实际影响决定，默认运行相关检查；跨包影响需要扩大时才运行相应的整体检查。角色、仓库操作说明和工单使用一致规则，不机械要求每个参与者重复全量套件。已有检查证据对应的代码未受影响时可复用；产品行为要求和真实用户路径验证不因缩小检查范围而删减。

## 执行模型

工单领域管理任务、交接、派发条件与成果，普通会话管理聊天与运行事实。确定性派发和监工生命周期遵循[工作与工单](PRD.md)，监工判断与处置由角色 prompt 定义。

`needs` 只声明共享且不能同时操作的具体对象，同一对象使用同一资源名。独立实例不声明资源，工具类别 `browser`、`desktop` 不作为互斥资源名；前置工单只用 `dependsOn` 表达。资源声明不提供跨 workspace 互斥保证。

程序派发、CLI/RPC 与界面使用同一套业务动作校验；状态所有权、事务和事件顺序统一遵循[架构](../../Foundation/Architecture.md#持久化与事务)。

运行记录格式不受支持时明确报错并停止该工作区的执行，不忽略记录或把已有工作当作新任务派发。存量数据转换与正常调度分开，转换前结束持有这些记录的运行实例。

等待必须有可查询的原因和恢复条件；重试续接未完成动作，保留原会话与成果，不重复已完成的外部操作。

## 轮次与恢复

业务阶段和会话运行状态分别拥有事实来源，语义遵循[执行控制](PRD.md#执行控制)与[运行失败与恢复](PRD.md#运行失败与恢复)。业务状态只由有效的业务动作转换，不从普通消息、轮次结束或角色文本推断交接。

派发、显式继续和合入登记核对目标及当前事实，同一业务动作不重复启动。业务记录写入遵循既有事务边界，不跨模型轮次持有锁。轮次结束只更新所属运行事实和占用，不自行生成下一轮任务；迟到事件不覆盖后续已发生的业务操作。

普通发送、追加、停止和受理结果使用现有会话通道，工单层不复制消息队列与确认状态机。后台连接和只读进度查询不隐含中断或强制重载；发送结果不明时依据会话层可核对的事实处理，不以新消息盲目重发。

## 执行消息

会话读取与通信复用现有引擎和会话定位边界；`asksource` 等待模型答复时不持有工单或 workspace 事务锁。临时询问 fork 的归档在收尾路径执行，归档结果与答复结果分别报告。产品行为见[角色与执行](../Roles/PRD.md#会话)。

准备与 Worker 首次派工提供完整说明；同一会话后续消息只携带本次有效增量，不重复身份、工作目录规则、历史记录和通用提交要求。固定会话保留上下文，不重放已经交付的业务通知。

决策答复包含对应问题、所选选项、用户备注，以及等待期间尚未告知的工单调整。引用文档合入通知包含合入 SHA、相关文档 diff 和重新读取最新工单后继续的指令。同一消息内每项答复或调整只出现一次，历史记录保留供查询。

需要交付的合同、文档、退回与决策内容关联其业务记录，交付结果与业务操作一并可查询；不把普通聊天存入工单，也不另建通用消息中间件。合同调整与文档合入的 RPC 携带发起会话，服务层以它与工单执行会话的对比判定是否回送；没有发起会话的调用视为外部变更。引用范围、定位校验与逐条变更规则见[引用定位](PRD.md#引用定位)。

## 状态与回收

业务执行由 Worker 完成，异常判断由监工完成，程序负责确定性动作校验。自动合入、原 Worker 处理合入及回滚共用工作台的串行边界；跨模型轮次的等待不占住服务事务锁。同一合入不并发执行，完成登记核对实际 Git 结果。业务行为见[合入进度与处置](PRD.md#合入进度与处置)。

工单完成、会话历史和目录回收相互独立。目录归属与使用状态以回收时的记录为准，登记、复用与回收遵守同一串行边界。退订应答不等于执行环境已经卸载，目录占用不阻塞工单结束。回收行为见[工单](PRD.md#流转)，历史读取与执行环境边界见[架构](../../Foundation/Architecture.md#会话与执行环境)。

工单状态、提交与恢复行为见[工单](PRD.md)，决策与结果展示见[Inbox](../Inbox/PRD.md)。
