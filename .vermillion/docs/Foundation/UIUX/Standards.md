# UI/UX 开发维护规范

新界面从共享组件和主题变量长出来，不从零写样式。每个页面只做内容和动作，布局、状态、字号由公共层决定。信息按本文的表达模式呈现：状态用图形，技术原文翻成人话，一屏只突出一个主角。各主要页面的参考形态见[界面参考样张](UI-Sample.html)，其中的数据只是示意。

## 从哪里开始

- 应用壳组件入口：`apps/desktop/src/ui/app/components/ui.tsx`。文件头列出全部可用组件；先在这里找，再看相近页面（`InboxPanel`、`WorkspacePages`、`DocsPanel`、`SessionSidebar`）的真实用法。
- 主题变量：`apps/desktop/src/ui/app/app.css` 的 `@theme` 块。字号档位 `text-micro / caption / label / body / title-sm / title`，颜色 `text-strong / foreground / muted-foreground / faint-foreground`，表面 `bg-surface / surface-raised / surface-hover / surface-selected / input`，边框 `border-border / border-strong / control-border`，圆角 `rounded-sm / md / lg`，字距 `tracking-eyebrow`。
- 会话区（`ui/chat-shell`）保留自己的 `awb-*` 样式；应用壳和 `features/` 只用上面两处，不引用 `awb-*` class。会话区里嵌入的业务块（turn 扩展）用 `app.css` 里的 `vm-*` 块。

## 必须复用的结构

| 需要 | 用 |
|---|---|
| 分页主体的页头：标题、概况计数、主操作 | `PageHeader` |
| 面板顶部一行标签 + 右侧动作 | `PanelHeader` |
| 列表里的一行：前导 / 标题 + 次行 / 尾部状态，可选中、可嵌套 | `ListRow` |
| 当前没有内容时的说明和下一步 | `EmptyState`（一个视图一个，不叠加） |
| 标题下的一句说明或错误 | `InlineNotice` |
| 需要用户操作才能继续的异常或等待：原因、下一步和操作 | `Alert` |
| 表单输入、文本域 | `Field` |
| 单选下拉（含 workspace、模型等选择） | `Select` |
| 同一列表的视图切换（进行中 / 已结束 / 全部） | `SegmentedControl` |
| 开关类设置 | `Toggle` |
| 只有图标的按钮 | `IconButton`（必带 `label`） |
| 普通按钮 | `Button`，变体只有 primary / accent / secondary / ghost |
| 短标签、风险等级 | `Badge` |
| 对象状态 | `StatusPill` |
| 数量进度（已合入 / 总数、通过 / 总数） | `Progress` |
| 有固定阶段的生命周期 | `Steps` |
| 弹窗、右键菜单、diff | `Modal`、`ContextMenu`、`DiffDialog` |

页面可以安排这些组件的外部布局；不跨层覆盖组件内部样式。出现新用途时扩展 `ui.tsx` 的接口并检查已有使用处，不在页面里复制一份。

下拉、分段切换和菜单都用应用自己的弹出层，不使用系统原生 `<select>` 下拉，保证高度、箭头、弹出样式和键盘操作一致。

通用会话组件只接收展示数据、渲染插槽和操作回调。工单查询、事件订阅、Worker 分支业务投影及状态文案由应用壳提供，会话区不反向依赖应用壳的 Context、工作台客户端或业务类型。

## 导航与状态保留

- 主导航上方是工作台和 Inbox，设置位于底部且与两者同级。设置以弹窗打开，包含新会话引擎、标题模型与各引擎程序路径，见[会话引擎](../Engines/PRD.md)。
- 工作台左侧会话列表常驻，新建会话旁放「全部」/ workspace 筛选下拉；筛选只影响列表，不切换当前会话。具体 workspace 筛选作为新草稿的默认项目。
- 右侧顶部分页固定为会话、工作、领域、角色、Issues、自动化、管理。会话默认打开，SessionPane 与右侧 Docs Explorer 在切页时保持挂载并保留草稿。分页标签可带计数，只统计需要用户处理的事项，为 0 时不显示。
- 会话以外的分页在分页栏右端显示紧凑的 workspace 选择器，明确编辑范围：显示 workspace 名称，完整路径只出现在展开列表的次行；「全部」仅是会话列表筛选值。页面内容不再嵌套导航分页；对象列表（领域）可用左列主从布局，左列固定宽度，右侧详情限制在可读宽度内，区块标题与其操作按钮左对齐相邻，不把按钮推到页面最右。领域草稿在切页时保留。
- 工作和工单链接进入工作台 → 工作并定位目标；会话链接进入工作台 → 会话并选中目标会话或树内节点。Inbox 保持弹窗与展开页面行为，设置只以弹窗打开。

## 页面骨架与层级

- 会话以外的分页主体固定为：页头（标题、概况计数、主操作与页面级设置）→ 筛选条（视图切换、文字筛选）→ 内容。概况计数可以直接作为筛选入口。
- 一屏只有一个主操作使用 primary；其他操作用 secondary 或 ghost，行内操作用图标按钮。
- 有状态的对象列表按“需要用户处理 → 进行中 → 已结束”分组，组标题带数量；已结束默认只显示最近几条，其余经视图切换查看。需要用户处理的条目不和历史条目混排。
- 层级靠字号、字重、间距和分组标题区分；相邻层级长相必须不同。卡片只用于一个独立对象（一份工作、一个设置组），不嵌套卡片。
- 行内操作在 hover 或聚焦时出现，位置固定并始终占位，不改变布局。

## 信息表达

同类信息使用同一种画法，页面按下表选用，不自行发明：

| 信息 | 画法 |
|---|---|
| 对象状态 | `StatusPill`：状态图标 + 简短文字，用状态语义色的浅底和文字色 |
| 列表行状态 | 行首 18px 状态图标：进行中转圈、完成对勾、失败叉、等待虚线圈、暂停双竖线 |
| 数量进度 | `Progress` 分段条，旁边写“0 / 1 已合入”这类数字 |
| 固定阶段的生命周期 | `Steps`：节点加阶段名，已过阶段带时间，当前阶段突出，等待原因附在当前节点下 |
| 验收、检查清单 | 每条前置状态图标，条目用正常字重，证据默认收起 |
| 属性和元信息 | 标题下一行“图标 + 值”，用 `·` 分隔；多项并列时用两列键值 |
| 需要用户处理的异常 | `Alert`：一句原因、一句下一步和对应操作 |
| 同一对象的多组材料 | 带计数的标签页（验收 4/4、审阅 2），不堆叠多个折叠卡 |
| 相似记录的重复 | 合并为一行并写明次数和时间范围 |

同一状态只在一个地方表达；其他位置讲“怎么走到这里”，不重复“现在是什么”。标题和正文里出现的 Markdown 一律渲染，不显示反引号、方括号链接这类源码。

## 技术数据

技术原文先翻成用户能读的形态，原文放进可展开的详情：

- 工具调用写成“动作 + 对象 + 结果”，例如「读取 README.md · 3 行」「运行 git status · 无改动」「列目录 项目根目录 · 12 个文件」。命令行、转义字符和退出码只在展开详情里出现；失败的步骤用失败色标出结果。
- commit 显示前 7 位，可点击复制；id 用等宽字体放在弹窗底部或详情里，不进标题行。
- 路径优先显示文件名，目录作为次级文字；完整路径放在悬停和详情里。
- 报错写成原因和下一步，引擎或命令的原文进技术详情。
- 内部枚举和字段值（`done`、`turn`、`completed`、run id、stage）一律映射成中文描述，映射集中在对应的文案模块。
- 时长写成“1 分 27 秒”“已运行 31 分钟”；时间在列表中用相对时间（刚刚、3 分钟前、昨天 22:10），不用“0m”“2m”这类缩写。

## 视觉规则

- 整体单色、低饱和；主操作靠明度和位置突出，正文与说明文字不上色。
- 状态语义色只有五种，都取低饱和值：进行中黄、完成绿、失败灰玫红、需要用户处理琥珀（偏橙，与进行中的黄色明显可分）、信息灰蓝；取消和已结束的其他结果用中性色。语义色用于状态图标、`StatusPill`、进度条、计数、选中色条和 `Alert` 的浅底，不用于正文或大面积底色。输出面板的严重级别标记沿用这组颜色：错误用失败色、警告用需要用户处理色、信息用信息色，变量为 `--awb-severity-*`。
- 会话树节点与会话列表行使用同一组状态色：黄色表示进行中、绿色表示已完成未读，已读为中性色；Worker 节点显示 W，当前位置轮廓独立于状态色。
- 自然语言、区块标题和短标签使用无衬线字体和正常字距，不强制大写。等宽用于代码、路径、id、commit 和时间；两类字体栈都显式指定中文无衬线回退 Microsoft YaHei UI / PingFang SC。
- 界面自有文案（导航、分页、区块标题、按钮、菜单项、空态、状态说明和会话区的过程描述）用中文，Docs、Domain、Automation 分别写作文档、领域、自动化。对象标识、角色身份和技术产物保留原文：workspace、Worker / Reviewer / Verifier / Maintainer / Liaison、commit 与 diff、id、路径、模型名、引擎名；Inbox 与 Issue / Issues 也用原名。
- 空态和说明文案平实直述，不用拟人化或口号式语气。
- 同一状态只在一个地方表达。多个面板不重复催促同一操作。
- 主要内容区保持可读宽度；辅助区域没有内容时不占据强布局地位。
- 工单状态与合入进度遵循[工单](../../Workbench/Missions/PRD.md)，文案由 `task-labels.ts` 集中提供，形态按上面的状态语义色和[信息表达](#信息表达)呈现。同一列里的状态宽度一致，保证对齐。
- 破坏性动作（取消工单、删除领域）不直接摆在行或卡片上：行级的收成 hover 才显示的 × 图标且固定占位，卡片级的收进「···」菜单。删除领域、移除 workspace 这类不可撤销动作点击后弹窗确认。查看类动作（会话、来源）用带 hairline 描边的 `Button variant="ghost"`，和旁边的元信息文字分得开。
- 列表行的尾部动作列宽度固定，行与行之间的按钮、状态列必须对齐；hover 只改透明度和底色，不改布局。
- 时间在快速查看场景用相对时间（3 分钟前、昨天 22:10），页面模式可附完整时间和 commit。
- 弹窗承载的面板不放左侧导航列；需要切换对象时用标题栏里的下拉。开关、下拉这类单值配置直接放在页面上改动即保存；只有多选树、多行条目才进弹窗。目录勾选树使用三态复选框：子级部分勾选时父级显示半选，勾选父级即覆盖全部子级。弹窗展开为页面时保持当时所在的分页、选中项和展开状态。
- 开关旁写明当前状态或其作用对象，打开时轨道使用完成绿，关闭为中性灰；不能只靠灰度区分开关状态。

## 间距与图标

- 间距只用 4、8、12、16、24、32px 六档：同一行内元素 8，同组行之间 4–8，卡片内边距 12–16，分组之间 24，页面左右留白 24–32。
- 列表行高两档：紧凑 32px（树、菜单、步骤），标准 44px（工单、角色等对象行）。
- 图标来自 lucide，统一描边粗细。正文与按钮里 14px，元信息行 12px，与文字垂直居中，图标与文字间距 6px。
- 固定对象使用固定图标：会话 MessageSquare、工单 ListChecks、文档 FileText、文件夹 Folder、commit GitCommit、分支 GitBranch、合入 GitMerge、workspace Folder；工具动作：思考 Lightbulb、读取 Eye、列目录 List、搜索 Search、编辑 Pencil、运行 Terminal、网络 Globe。同一对象在各页面使用同一图标。

## 文字与控件

应用壳与会话区共用下列可读性规格，包括输入器配置、空态、说明文字和短标签。原尺寸示意见 [文字打样](Type-Sample.html)。

| 档位 | 字号 | 用途 |
|---|---|---|
| micro | 12px | 时间、标识、短标签、区块标题 |
| caption | 12.8px | 次行、提示、空态说明 |
| label | 14px | 列表标题、按钮、配置标签和选中值 |
| body | 15px | 正文 |
| title-sm | 16px | 小标题 |
| title | 17px | 页面与弹窗标题 |

界面文字最小 12px。列表标题、按钮、配置控件、短标签及区块标题用 500 字重，正文与说明用 400，页面标题用 600。正文行高 1.55，说明行高 1.45。需要阅读的辅助文字使用 muted（#9a9a96），正文使用 foreground，主要标题及选中值使用 strong；faint 留给装饰与禁用状态，不承载正常可读的说明。

输入器配置控件高 32px、14px，主值明亮、附属值中灰，控件内部文字不折行，空间不足时按完整控件换行。短标签为 12px、500 字重，普通标签高至少 20px、正常字距，文字使用 foreground；浅底色或细边框表达分组，状态形态保留各自语义。

## 检查

- `pnpm --filter @vermillion/desktop lint:ui`：拦截 `ui/app` 和 `features/` 里的硬编码颜色、任意字号/圆角/字距、`awb-*` class、裸 `<input>/<textarea>/<select>`。确需例外的元素加 `data-ui-raw="原因"`。
- 改公共组件或 `app.css` 后，起实例打开 工作台 → 会话（会话列表 + Docs Explorer）、Inbox、工作台 → 工作 三个页面，看普通状态、空态、长中文标题、错误和窄窗口。截图交给空白 subagent 对照本文判断，不自己看图下结论。
- 涉及界面的工单，verifier 除了逐条 acceptance，还要对照本文看一遍截图：是否用了对应组件、是否出现规则之外的颜色和字号、重要操作是否被弱化到看不见。页面在[界面参考样张](UI-Sample.html)中有对应形态时，截图与样张并排比对信息层级：分组方式、状态画法、技术数据是否已翻译、主操作是否唯一。样张只约束形态，数据以真实实例为准。
