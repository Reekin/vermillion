# 界面响应与诊断规范

## 订阅与输入

消息区只实时订阅可见 turn 路径。后台内容按批次接收并保存，后台运行、完成、失败、审批和等待输入保持通知。切换路径读取最新内容，输入草稿独立保留。后台正文不驱动当前输入区和正文重新渲染。

会话树的状态刷新不重复加载未变化的正文，也不因其他已加载会话及历史增多而放大一次局部内容更新的处理成本。多分支运行、结束或等待用户时，当前节点的输入与浏览保持响应；切换分支后内容完整、状态及时，已加载历史与未发送草稿保留。

## 卡顿记录

桌面默认开启有界诊断。输入延迟分为事件产生到处理函数开始的排队时间，以及处理函数开始到下一帧的等待时间；中文输入事件同样覆盖。记录长任务、事件循环延迟和同一时间范围的事件排队、store 更新、正文投影、React 渲染至提交以及会话树查询耗时。

操作记录使用内存环形缓冲，告警关联附近操作后写入已有 `logs/perf-<UTC日期>.jsonl`，正常短操作不逐条写盘。频繁告警限频，汇总计数仍保留。日志记录时长、数量和会话标识，不记录输入文字、按键值、命令正文或消息内容。

页面隐藏时不把定时器节流和暂停的动画帧计为前台输入卡顿；重新显示时重置计时基准。后台长任务仍记录，并标注页面可见状态。

同步操作、异步等待与渲染至提交的墙钟跨度分开解释。相邻或重叠的操作用于缩小排查范围，不能仅凭时间重合认定因果，也不能把嵌套跨度累加成 CPU 耗时。没有匹配操作的长任务保留为未归因，后续用运行时采样区分布局、垃圾回收和其他执行。

## 读取

在仓库根运行 `node scripts/diagnose-ui-stalls.mjs --minutes 15` 查看最近卡顿；`--session <id>` 限定输入所在会话，`--base-dir <目录>` 指定隔离实例数据目录，`--json` 输出原始诊断与汇总。重新启动桌面后使用最新监测代码。
