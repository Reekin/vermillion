# 工单执行与恢复

覆盖开工、工单的调度、执行资源声明、依赖、文档变更通知、决策答复、验收提交、主分支合入、后台 worktree 回收，以及运行中断后的恢复。

修改工单状态、执行记录的持久化与查询投影、CLI/RPC 入口、运行事件、角色执行指令、重试与恢复逻辑时应考虑这个领域。涉及工单看板、决策卡或角色界面时同时考虑 UI/UX 领域。单纯修改工单所实现的业务功能、且不改变执行流程时不涉及本领域。

## 开工入口

输入器为空时，「开工」直接登记请求，从当前查看的节点派出准备分支，发送配置的准备提示。所选节点仍在运行时，等待该 turn 结束再派出分支。

输入器有内容时，「发送并开工」直接登记请求，把用户输入与配置的准备提示合成准备分支的第一条消息，保留附件、技能引用及本次模型选择。不会先让设计伙伴运行一轮登记开工。[用户：我点击的时候就直接把开工跟我的输入拼起来发给它了]

已有讨论从当前查看节点派出准备分支，原讨论保留在原位置；New Chat 直接以合成消息开始准备，无需先生成讨论 turn。请求未成功接收时保留输入内容。

准备分支整理文档并建单，结束 turn 后等待调度；调度排到工单时才注入 Worker 指令并开始执行。两种按钮入口使用相同的准备与执行流程。
